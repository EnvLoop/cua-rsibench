# Odoo v0.6.6 two-frame dispatch amendment

The independently audited v5 attempt stopped at a source-document click.
Its six dispatch samples were the same allowed two-pixel RFQ border alternate,
but the final physical PNG returned exactly to the observed PNG. The frozen
v5 guard required that final PNG to remain the alternate. It rejected before
`mouse.click`; the original attempt and its source freeze are immutable.

The additive v6 adapter preserves v5 parsing and all non-RFQ dispatch rules.
For a purchase RFQ click, it first obtains the existing bounded physical
samples. If they return to the exact observed PNG, that PNG is the only
permitted final member. If six identical pinned-border alternates are proven,
the final member may be either the full observed PNG or that one full
alternate PNG. A third image is rejected. The adapter takes two final full
screenshots and requires them to be byte-identical. It verifies the same task
binding, frame identity, URL, and enabled visible target control with
unchanged ref, role, label, and bounds outside the border before the click.
Both final PNGs and every earlier guard sample receive unique indexed,
hash-bound private references. The independent v6 auditor reopens every
indexed image and rejects an unbound, reordered, third, or changed sample.

The [public source freeze](../evidence/odoo-v066-two-frame-v6-source-freeze-2026-09-29.json)
binds the adapter, evaluator copy, auditor, plan and gate sources, and offline
mutation tests. A separate owner-only freeze binds that public freeze to the
preserved v5 failure before a fresh candidate plan is written. The
[field-limited public plan](../evidence/odoo-v066-selection-two-frame-v6-evaluator-plan-2026-09-29.json)
commits to a new random run nonce without publishing task content or the
nonce. The same underlying selection task can be evaluated only in a new
run directory; no old action or attempt is replayed.

This is source-only preparation. The v6 no-GUI current SQL/full-filestore
gate, its independent audit, source-document GUI readback, positive and
wrong-object saved-state controls, visual review, researcher campaigns, and
official final admissions remain pending. No v6 Docker, GUI, or model call
has occurred.
