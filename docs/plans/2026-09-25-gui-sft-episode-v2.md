# Cell-neutral GUI SFT episode v2

`gui-sft-episode-v2` is a **data admission contract**, not a claim that six application cells already have training episodes. It accepts the same screenshot-plus-current-controls and minimal validated GUI action grammar for Magento administration, GitLab, Odoo, Excel for the web, PowerPoint for the web, and LibreOffice desktop. Its adapter labels are explicitly mapped to the six frozen `full_study_matrix_v1.CELLS` identifiers; the proof output carries that canonical study cell ID. The application adapter owns login, mask policy, reset, and action dispatch. The v2 validator sees only a train-only episode, four independent verifier receipts, and separate selection/final manifests; it never calls a browser or model service.

Each step binds a masked PNG byte sequence and SHA-256 to one current observation and one strictly normalized `scale-computer-use-v0.6` JSON action. Refs must be visible and enabled in that frame; coordinates must be inside that image. The model prompt contains the current task instruction, screenshot, visible controls, previous GUI-action status, and optional memory produced by the prior assistant action. Source identity, verifier results, split manifests, SQL, and artifact gold never enter the model-facing turn. Unsupported UI operations such as Magento's native state selector remain unsupported until a separately versioned train/evaluation action contract admits them.

Admission requires four hashed receipts from evaluator-owned artifacts: a successful task evaluator, a failed negative control with independent state discrimination, independent saved-state readback with non-target preservation, and semantic state equivalence after reset. The receipt files also bind to their original source artifact bytes. A missing, tampered, or merely asserted gate rejects the episode. The validator checks task ID, entire intent template, and declared entity tags against **both** selection and final manifests, then checks selection/final task, template, and declared-entity disjointness. Manifest source revision and dataset SHA-256 must match the train source. `declared_hints_only` reports the current Magento source extractor's limited entity coverage; it is not a full database-record isolation proof.

One measured replay converted the admitted, quarantined Magento task-777 action-only episode from v1 without changing any of its **36 assistant action dictionaries or 36 masked screenshot bytes**. The four receipts link the unchanged official positive, a separate wrong-object negative, persisted SQL/search readback, and reset. The v2 split input was the SaaS planner's 20 selection and 100 **provisional** final candidates; task 777, template 742, and its five products were excluded. These candidate counts do not make any task officially admitted to final evaluation.

The pinned Qwen3.8-27B cookbook renderer built **36** image-plus-action datums offline with positive assistant loss, at most 2,610 supervised tokens per datum. This v2 replay made **zero** paid Tinker calls and did not evaluate a trained checkpoint. The earlier one-step paid v1 compatibility smoke remains a distinct, train-only development result.
