# Magento GUI SFT Data Gate

This bounded development gate records a train-only technical demonstration on WebArena-Verified Magento-admin price task 777. The host logs in and selects teacher actions, but each recorded edit is a validated current-frame GUI action. Each target action is paired with the exact masked screenshot and visible control list observed before dispatch.

The episode remains private under ignored `work/`. A builder refuses to render Tinker datums until the unchanged published evaluator, independent SQL and search-index readback, and post-task reset all pass. The recorded assistant actions omitted optional memory, so a separately hashed action-only derivation strips teacher-host memory from model-facing observations while preserving executed action bytes and masked screenshots. The public evidence contains both hashes, counts, and a split exclusion. Task 777, intent template 742, and its five product entities are quarantined from final evaluation. Historical base-model task-777 diagnostics remain pre-training records, not a held-out comparison after checkpoint training.

An attempted order-address task 538 exposed a separate action-space gap: the state selector did not respond to the allowed arrow/page keys in headless Chromium. A CMS title task 486 was also rejected when the unchanged network evaluator scored the native save zero. Neither attempt produced an admitted SFT episode. A future native-select action or CMS evaluator repair needs its own protocol revision; neither may be represented as successful student training data.

Offline rendering uses the pinned Qwen3.8-27B `qwen3_5_disable_thinking` renderer and requires image chunks plus positive assistant loss. No paid optimizer step or trained improvement is implied by this gate.
