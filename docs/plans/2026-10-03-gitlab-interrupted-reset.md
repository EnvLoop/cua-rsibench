# GitLab interrupted reset recovery

The original full100 run completed two control trios and saved the third
positive. KeyboardInterrupt interrupted its next cold boot. TaskWorld14 catches
Exception at that boundary, leaving the positively claimed cycle alive while
active_index is still unset. Parent release then failed and original resume
could not acquire the loopback port. The partial case receives no credit.

The exact original Docker launch ID, current image and mount roots, parent inode
and ownership token were reopened before recovery. Only that owned cycle and
parent subtree were removed; original volumes and immutable seed remained.
The original container was restored. Its declared bridge endpoint had been
lost after the previous failed start, so the same bridge and existing loopback
8018 binding were restored. SQL, complete Git trees, original container identity,
protected source and seed then matched the saved baseline. No failed task was
replayed or promoted. The network restoration receipt explicitly records an
optional-field preflight error and that its receipt was written afterward.

The additive interrupted-reset component catches BaseException at the one
positively claimed partial-boot cleanup boundary. Five tests cover keyboard
interrupt, async cancellation, SystemExit, ordinary errors, unclaimed resource
refusal, cleanup failure and unchanged ancestor methods. The original V14 bytes
remain frozen. This component has not yet been integrated or ratified across
the seven actor roles; its tests are not an application qualification.

Integration must preserve the startup settings, source ratification, original
20/20/100 allocation, exact independent SQL/Git reset, 90-action/720-second actor
budget and ownership checks. New source-bound controls are required before
model sampling or full-study admission. Reusing partial historical controls is
not permitted.
