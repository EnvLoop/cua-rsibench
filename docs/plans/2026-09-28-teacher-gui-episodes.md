# Train-only teacher GUI episode collection plan

**Goal:** Connect a frozen researcher proposal to native or web GUI teacher episodes and a v0.6.6 Qwen training batch without admitting selection or final tasks.

**Boundary:** The campaign dispatcher owns six-cell ratification, task views, append-only paid reservations, and Tinker training. The new adapter owns only teacher episode collection and train-batch rendering. A cell worker owns the original software, visible GUI observation and action dispatch, saved-artifact readback, independent verification, and reset. The adapter rejects any worker receipt that does not bind those artifacts to the selected train task and frozen runtime. It cannot itself establish that a cell worker is genuine; that remains an external cell-admission and source-audit requirement.

1. Validate the frozen six-cell ratification and immutable witness, mode-0600 proposal, journal hash, train context, cell worker identity, teacher model configuration, multimodal harness, route rate card, and empty ignored output directory **before** a paid call.
2. Give the worker only the selected train task and two callbacks. The teacher callback sends the current screenshot and v0.6.6 action prompt through one separately reserved `teacher_rollout` transaction per frame, normalizes the response against that exact frame, and retains its receipt. The E2B callback reserves full lease hours and peak concurrency before sandbox creation; local workers need no E2B call.
3. Require the worker to return byte-bound frame and action-trace references plus independent saved-state and fresh-reset receipts for each episode. Admit only a successful original-software train episode with no unintended changes and a terminal GUI `finish` action. Preserve failed or uncertain paid attempts; never regenerate them automatically.
4. Render the accepted turns with the frozen Qwen vision renderer using the v0.6.6 prompt. Write the exact private dataset manifest expected by `dispatch_tinker_sft`; return its path and the in-memory datums, prompts, and canonical render receipt.
5. Test with fake paid services and a synthetic worker: valid train batch, hidden-ID rejection before provider calls, bad ratification, tampered screenshot/action/state/reset receipts, uncharged E2B creation, ambiguous model/usage, and exact manifest hash. No real model, GUI, or hidden task runs in these tests.
