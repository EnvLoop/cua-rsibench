# Odoo twenty-task trial

The current user-directed experiment uses one application, Odoo Community, with 20 frozen final tasks: five purchase, inventory, sales and CRM tasks each. The public TRAIN20 and selection20 partitions remain separate. The original 100-task candidate world and previous runs are preserved. This pilot does not establish completion of the six-application study.

The researcher and native rollout teacher request `gpt-6-sol` through AgentRouterHub Responses. The Tinker student remains `Qwen/Qwen3.8-27B`. The user explicitly discontinued Sol 6.1. Sol 6.1 failure records remain separate.

The experiment sequence is:

1. Validate an actual train-only Sol 6 researcher proposal against public TRAIN20 identities.
2. Collect native GUI teacher trajectories from the proposed training tasks, retaining only independently passed saved-state results with exact reset and restored services.
3. Render authentic screenshots and actions with the same Qwen vision recipe used by the student. Run actual Tinker LoRA updates and retain sampler-checkpoint lineage.
4. Select a checkpoint using the separate selection20 partition before inspecting final outcomes.
5. Evaluate the base model and selected checkpoint on the same frozen final20, with identical native action and time limits, the original independent verifier, reset checks and service restoration.
6. Publish an English pilot report with per-task outcomes, infrastructure failures, action counts, timings and authentic usage where available. Render and visually inspect its PDF and figures.
