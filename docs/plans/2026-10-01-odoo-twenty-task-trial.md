# Odoo twenty-task trial

The current user-directed experiment uses one application, Odoo Community, with 20 frozen final tasks: five purchase, inventory, sales and CRM tasks each. The public TRAIN20 and selection20 partitions remain separate. The original 100-task candidate world and previous runs are preserved. This pilot does not establish completion of the six-application study.

The researcher and native rollout teacher request `gpt-6.1-sol` through AgentRouterHub Responses. The Tinker student remains `Qwen/Qwen3.8-27B`. Old Sol 6 proposals belong to a previous configuration and cannot be counted as Sol 6.1 results. No fallback model is selected.

On October 1, an authenticated public-marker-only request returned HTTP 404 with `model_not_found`: the current API-key group has no configured account supporting `gpt-6.1-sol`. The model catalog also omitted that exact identifier. The frozen model configuration is ready; native teacher and training dispatch must wait for route access or a user-confirmed exact Sol 6.1 identifier. Unknown billing remains null. The route check has no task, model-outcome or training credit.

The experiment sequence is:

1. Validate an actual train-only Sol 6.1 researcher proposal against public TRAIN20 identities.
2. Collect native GUI teacher trajectories from the proposed training tasks, retaining only independently passed saved-state results with exact reset and restored services.
3. Render authentic screenshots and actions with the same Qwen vision recipe used by the student. Run actual Tinker LoRA updates and retain sampler-checkpoint lineage.
4. Select a checkpoint using the separate selection20 partition before inspecting final outcomes.
5. Evaluate the base model and selected checkpoint on the same frozen final20, with identical native action and time limits, the original independent verifier, reset checks and service restoration.
6. Publish an English pilot report with per-task outcomes, infrastructure failures, action counts, timings and authentic usage where available. Render and visually inspect its PDF and figures.

Task selection uses the fixed seed recorded in [the freeze receipt](../evidence/odoo-twenty-task-trial-freeze-2026-10-01.json), with no model outcomes in the sampling rule. Hidden instructions and answers are withheld from the researcher and teacher. A separate explicit single-environment authority is used; the original six-environment authority is not fabricated or weakened.

The first teacher attempt failed before native or provider execution because required source-binding arguments were absent. Its namespace is preserved. The source now supplies both native runtime and verifier bindings. It remains pending a fresh live qualification after model access is restored.

The source review also identified execution-readiness work before collecting a fresh teacher episode: preflight the vision renderer before paid work; prevent rejected native actions from becoming positive SFT targets; and distinguish HTTP-client closure from completed outstanding deadline callbacks. The renderer and image recipe are shared with student inference, but exact prompt-token equality has not been established. These findings carry no native qualification or training credit.

The Sol 6.1 configuration and evidence-binding checks passed 28 local tests. They include rejection of older-model proposals, changed screenshots/actions/saved artifacts/reset evidence, and confirmation that the historical teacher namespace and native source binding remain unchanged. Synthetic test artifacts are not benchmark outcomes.
