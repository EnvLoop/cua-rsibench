# Original PowerPoint-for-the-web source replacement (pre-result design)

**Status: offline candidate source built; no GUI admission or final result.** The public PPT-Eval screen yields ten final source decks and discoverable answers. Its 100 task IDs remain useful development comparators, but cannot establish a sealed transfer exam. This dated plan selects a separate, authored set of Microsoft PowerPoint-for-the-web tasks built from the pinned, [CC BY 4.0 World Development Indicators snapshot](../../native_desktop_factory/source.py). The data observations are authentic WDI values; the analyst decks, briefs, policy memos, and deliberate defects are EnvLoop-authored simulations, not historical government or company presentations. See the [aggregate offline candidate receipt](../evidence/ppt-wdi-original-offline-inventory-2026-09-25.md); it is not an Office-web save/download proof.

The existing WDI cube contains 35 countries × five indicators × six years with no missing values. A source-country-disjoint provisional split can reserve five countries for 20 training tasks, five for 20 selection tasks, and 25 for 100 final candidates, four task instances per country. This would give 25 final source families, not 100 independent countries. The 100 instances need separate deck files and seeded worlds; family-level analysis must cluster the four related tasks. A private seed and exact package hashes must be frozen before a researcher sees selection feedback. The public source values may be known to a pretrained model; only the authored task and held-out evaluator would be sealed.

Each deck should be a credible six-to-ten-slide economic monitoring brief with source-footnoted charts, tables, an executive summary, and a reviewer memo. A final task should require at least three dependent native edits across two or more slides after reconciling WDI data, with a plausible near-miss that fixes only part of the deck or changes the wrong series/year. Proposed final workflow families are: GDP level versus per-capita attribution; current-dollar versus percentage-unit correction; chart year-window repair; swapped legend-series repair; CPI versus unemployment narrative alignment; growth-rate calculation from two GDP years; ranking under an explicit comparator rule; cross-slide executive-summary consistency; source-footnote and table-year reconciliation; and scenario conclusion revised after a corrected indicator. These are semantic designs, not merely renamed slide templates. A pilot must reject any workflow that PowerPoint for the web cannot edit and save through visible controls.

The offline implementation uses eight of these causal patterns across the pinned indicators: stale GDP denominator, aggregate-versus-per-capita substitution, wrong CPI comparison year, one-year-versus-five-year labor change, wrong population base year, a population proxy substituted for per-capita growth, stale labor data in a price–labor spread, and minimum-versus-maximum watch-rule logic. It does not yet implement native chart-data repair, legend-series repair, or a country ranking task; those remain design options only. The Office-web pilot may reject additional workflows.

The independent verifier should compare a downloaded, Office-normalized OOXML baseline with the saved deck. It must check all target text, chart-data cells and series labels used by the task, source-year citations, untouched slide order and identities, media and notes preservation, and non-target geometry. A layout/visual check is required where OOXML alone misses an unintended design change. A score of 1 requires every dependent edit and no collateral alteration; partial edits receive 0 in the binary primary endpoint but may be recorded diagnostically. The evaluator holds exact targets and perturbation cases privately; researcher-visible inputs contain only the deck, task memo, and standard screenshot/action interface.

Before any of the 100 proposed final identities is admitted, demonstrate a fresh isolated OneDrive copy under the dedicated benchmark account, an untouched PowerPoint-web save/reload/download baseline, a known-positive visible-GUI sequence, a wrong-series/partial or collateral-edit negative, downloaded-artifact readback, same-file restore, and a **fresh-copy** reset from the frozen source. Repeat on every ID; a single deck control cannot stand for a family. Confirm account entitlement, download reliability, source rights, runtime/browser versions, Qwen observation/sampling, and cost limits. If original task content or evaluator answers leak into training or public artifacts, quarantine its whole country/workflow family before replacing it from unused WDI sources. No model score should be generated until this gate and the shared pre-campaign matrix pass.
