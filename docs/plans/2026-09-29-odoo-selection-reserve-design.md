# Prospective Odoo selection reserve design

This amendment addresses five vacant **selection** slots caused by a correlated purchase-source retirement. It does not change the 20-task denominator, any final-task identity, or the hidden gold. The retired five are terminal; the new cohort is prospective and has no inherited admission status.

## Allocation frozen before materialization

The five purchase slots are filled in retired-slot order by five fixed blueprints, one use per blueprint. A private 256-bit seed deterministically derives the cohort's new identifiers, vendors, SKUs, numerical source facts, target RFQs, and paired nearby RFQs. The public freeze records the seed commitment, generator source hash, existing task-manifest hash, blueprint-order hash, and exact allocation rule **before** the real seed is used to materialize any candidate. No outcome-dependent ranking, redraw, or replacement of a failing replacement is permitted. A failure is attrition under its new identity and requires a separately dated protocol amendment.

The five source types are one-page purchase operations records with distinct layouts and causal signatures: dispatch release, quality release, allocation desk ticket, rate exception, and split-shipment notice. Each identifies one authorized line on a three-line RFQ and supplies its quantity and USD unit rate directly. The target requires exactly two same-line edits. The supplier, promised dates, RFQ state, source attachment, two unaffected lines, and all unrelated records remain protected. Each candidate has a nearby wrong RFQ to make wrong-object edits a meaningful negative. This keeps the correction count, source-reading demand, original Purchase workflow depth, and preservation burden comparable to the retired selection cases while avoiding their supplier-confirmation layout and attachment-label recipe.

## Private package and pre-admission checks

The materializer writes five private case packages with one PDF per case, a source-backed oracle, a proposed Odoo seed delta, and a proposed 15-plus-five selection inventory marked **not admitted**. All gold, source values, entity names, and task IDs remain private. A separate offline auditor reopens saved PDF bytes, extracts visible source values, independently scores synthetic baseline/positive/wrong-object/partial/reset states, checks SHA-256 commitments, and compares task IDs, package/source hashes, template groups, and instance groups against existing train/selection/official task manifests. Entity names are checked against the available train and selection worlds; the hidden manifest is read only for identity/source/template commitments, without loading hidden candidate cases or gold. The reserve namespace is distinct from the existing train, selection, and hidden namespaces. A stronger hidden-entity projection remains a required evaluator-only pre-admission gate if namespace provenance is insufficient.

Offline controls are design evidence only. After review, the evaluator must build fresh original Odoo Community instances, show native GUI source opening and known-answer positive/negative controls, read saved SQL and physical filestore state independently, prove unrelated-state preservation and complete reset, then admit each replacement individually. Only five successful admissions permit freezing a revised 20-task selection manifest. No model selection, researcher campaign, or official final outcome follows from this offline package.

## Implementation sequence

1. Implement and test the deterministic generator and independent offline auditor using a test seed.
2. Commit source and design; create the real-seed public/private pre-materialization freeze and commit its public receipt.
3. Materialize exactly five private packages from that freeze; run the independent auditor and visual PDF QA.
4. Commit English field-limited audit evidence. Stop before Docker, GUI, or model execution pending root review.
