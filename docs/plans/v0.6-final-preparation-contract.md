# v0.6 offline final preparation contract

`tools/prepare_scale_final_v06.py` accepts one qualified cell and one frozen comparison slot. It verifies local evidence hashes and emits `intent.json` followed by `chunk-plan.json`. Neither file is a remote payload or an execution result. The tool has no dispatch path and never assigns scores.

The input JSON schema is `cua-final-cell-v0.6`, with these exact top-level fields:

| Field | Required content |
| --- | --- |
| `cell_id`, `researcher_id`, `role` | Slug identities; `role` is `base` or `selected`. The checkpoint is explicitly bound per slot. |
| `qualification_status` | Exactly `qualified`. Candidate inventories and one-task smokes are rejected. |
| `task_sets` | Exactly `train`, `selection`, and `official` arrays. Each row has `task_id`, `package_sha256`, `source_groups`, `template_group`, `instance_group`. `official` has exactly 100 unique task IDs, package hashes, and instance groups. Source, template, and instance groups must be disjoint across splits. Repeated source or template families within `official` are counted explicitly in the output; 100 instances are never called 100 independent families. |
| `qualification_evidence` | Relative `path` and SHA-256 for a JSON evidence file. It must use `cua-cell-qualification-v0.6`, match cell and source/runtime/action/verifier hashes, and cover all 100 official ID/package pairs. Its `cell_gates` provide byte-verified receipts for application access, software entitlement, and student observation/sampling compatibility. Each task records build and GUI save/readback checks and links byte-verified reset and independent-verifier receipt files. Reset receipts show a changed state restored to its initial hash; verifier receipts declare isolated evaluation, acceptance of the correct solution, rejection of an incorrect solution, and rejection of unrelated changes. These files are declarations and traces for an independent auditor, not proof that the underlying application run occurred unless the auditor checks their origin. |
| `bindings` | `source_snapshot`, `runtime`, `action_contract`, `verifier` each have a relative local file `path` and `sha256` verified against file bytes. `checkpoint` has `model`, `sha256`, and `freeze_receipt` with a local `path`/`sha256`. The receipt JSON uses `cua-checkpoint-freeze-v0.6`, matches cell/researcher/role/checkpoint, and declares `selection_frozen: true`. |
| `sampling` | Explicit integer `seed`, decimal-string `temperature`, positive `max_output_tokens`. |
| `execution` | `tasks_per_chunk` from 1 to 3, positive `max_actions_per_task`, `max_wall_seconds_per_task`, and `max_active_chunks`. A 100-task set with size 3 gives 33 full chunks and one one-task tail. |
| `cost` | `currency: "USD"`, `basis: "all_in_including_provider_compute_inference_storage_and_licenses"`, `spending_authorized_by_user: true`, plus decimal-string `task_usd_upper_bound`, `chunk_usd_upper_bound`, `authorized_ceiling_usd`, and `available_balance_usd`. The declared 100-task/chunk bound must fit both the ceiling and balance. Unknown or null values block preparation; the declarations are not a price audit or invoice. |

The output binds the exact manifest bytes, qualification and freeze receipts, source/runtime/action/verifier/checkpoint hashes, ordered task IDs and package hashes, source/template/instance cluster counts, sampling, execution limits, and declared cost bound. Chunk request IDs are deterministic. Rerunning with the same inputs preserves the original intent and plan. A changed source file, manifest, evidence file, intent, or plan is rejected. If preparation stopped after writing intent but before writing the plan, rerunning with identical inputs completes the plan. No partial chunk is padded or silently omitted.
