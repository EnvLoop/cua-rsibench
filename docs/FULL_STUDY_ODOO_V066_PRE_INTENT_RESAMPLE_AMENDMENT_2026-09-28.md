# Pre-result Odoo GUI frame-resampling amendment

The first original-Odoo v0.6.6 train-only pilot is retained unchanged. Its known-answer positive reached persisted SQL and physical source checks. During the wrong-object negative, a GUI `double_click` encountered `ContractError` after its observed PNG and assistant action bytes were saved but **before** a normalized pre-dispatch intent or GUI action result was written. The worker was cold-restored and its service state returned to the initial state. The old failure receipt records the exception class, not its `.code`; the exact `stale_frame` subtype is a runtime report, not an independently stored field. The [source-bound failed-attempt audit](evidence/odoo-v066-first-train-pilot-pre-intent-failure-2026-09-28.json) records that limit and keeps official/model outcomes at zero.

This dated amendment changes only the trusted train recorder's **pre-intent** observation handling. For one logical v0.6.6 GUI action it permits at most three total current-frame observations. If parsing rejects an observation with `stale_frame`, the recorder retains that raw observed PNG, rendered input and assistant JSON action, saves a rejection record with their hashes and the error code, waits a bounded 150 ms, then observes a new frame. Any other parse error stops immediately. After a normalized action intent is durably written, the recorder dispatches at most once. A stale frame, partial action, missing receipt or any other exception after that intent stops the attempt without replay.

A new mode-0600 train-only pilot binding and [public source freeze](evidence/odoo-v066-train-recorder-pre-intent-resample-freeze-2026-09-28.json) bind this recorder version to the previous failure audit, the same SHA-49f6 six-cell action ratification and the existing amended 140-ID Odoo plan. The replacement is the **new** private attempt directory `first-current-source-pilot-pre-intent-resample-01` for the **same train case**; the first directory and all its raw evidence remain untouched. No selection or hidden-final task values enter the live recorder. This is evaluator-control recovery before any official result, not a model retry, data point, campaign or changed final denominator. The independent saved-state/filestore/negative/reset pilot gate and post-review SFT gate are unchanged. **Official Odoo final tasks and model outcomes remain zero.**
