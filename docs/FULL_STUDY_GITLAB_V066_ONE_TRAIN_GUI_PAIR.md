# One source-bound GitLab CE v0.6.6 train GUI pair

**Status: code and fake tests only.** This train-only pilot selects the first
`issue_label_from_alert` task from the original CISA-anchored GitLab CE 18.5
private train partition. It does not send selection or final task content to
the actor or provider, run a researcher campaign, or admit an official final
task. Its private plan binds the current six-cell v0.6.6 ratification, exact
train package and instruction hashes, 20-train/20-selection/100-provisional
split evidence, non-admin partition ACL receipt, frozen PostgreSQL/Git
baseline, worker/verifier/adapter bytes, and a single no-replay output path.
The public plan contains hashes and aggregate counts only.

The positive arm reuses the existing original-GitLab teacher episode worker.
The Sol teacher receives one current screenshot, visible controls, and the
train instruction per call through AgentRouterHub Responses. A private intent
and full private request are saved before each provider POST, and the private
response and token usage are saved afterward. Every raw PNG is saved before
sampling. The worker checks the physical frame before and after the paid
callback, normalizes the model's one v0.6.6 GUI action, and applies it only
inside the assigned train project. It then reloads the saved page, scores the
persisted PostgreSQL/Git state with the independent train oracle, and cold
resets the original application to byte-equal baseline state. A failed or
uncertain provider/action call is retained and never replayed automatically.

The negative arm uses the same v0.6.6 observation/action backend on a fresh
clone of the **same train task**. It asks for a plausible but wrong priority
label on the active issue, preserving every other monitored record. The
independent oracle must reject the saved result, and an additional SQL/Git
shape check requires exactly one wrong `priority::p1`/`priority::p2` label
link on that issue with no unrelated change. The backend then performs a
separate exact cold reset. The negative is a verifier control, never an SFT
target.

The [independent auditor](../tools/audit_gitlab_v066_train_gui_pair.py)
reopens both arms' raw frames, request/response intents, full normalized
private GUI actions, source hashes, saved PostgreSQL/Git snapshots, positive
and negative oracle outcomes, and restored baseline artifacts. It also
revalidates the positive episode against the shared teacher adapter's exact
train-episode schema. Only a complete passing pair marks the **positive**
episode eligible for a later real Tinker GUI SFT batch. Eligibility is an
artifact gate, not a training step, checkpoint, model improvement, final
admission, or benchmark score.

The live sequence is: freeze the private/public one-task plan in the original
GitLab worktree; review its train-only and no-replay bindings; run one
explicit `record --execute` while the GitLab Docker lane is exclusive; run
the separate read-only auditor; then render/use the positive episode in a
bounded Tinker train batch. If either arm fails, retain its raw trace and
stop. All credentials, instructions, projects, provider bodies, screenshots,
actions, and gold remain evaluator-private.
