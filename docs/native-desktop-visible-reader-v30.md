# Bounded native Desktop reader

The actual V29 Calc diagnostic reached the owned X11 window and GI namespace, then completed MatchRule construction. Its first failed API stage was `collection_queries`: the first recursive `Collection.get_matches` timed out with `atspi_error` code 1. A finite result count therefore did not bound native subtree traversal work. The command completed with an unqualified diagnostic, and the owned guest was killed with a subsequent running-state check returning false. The full native error remains private; its SHA is `6f62ca3d54229ecbd392de6002c74fe51ac2286893d7752fd6bb20fa77fab51d`. This is infrastructure evidence, with zero task or model credit.

V30 uses read-only native state and geometry before requesting child counts. Hidden and offscreen branches are pruned. Native `MANAGES_DESCENDANTS` containers and child sets above the explicit cap remain deferred rather than being enumerated or represented as fully known. A requested physical point follows a bounded native Component hit path, checking the process, owned window ancestry, current native state and actual component geometry at every step. The resulting native child can override a broader parent target, including when the child is disabled. No cell selection is interpreted as keyboard focus. Keyboard access requires an actually observed `FOCUSED` object with editable, enabled and sensitive native states.

The reader limits nodes to 512, direct children to 128, depth to 32, target records to 128 and requested physical points to two. These source limits do not extend the existing 45-second diagnostic command, 55-second request, 90-action actor, 720-second actor clock or 1200-second guest lease. There is no recursive Collection fallback, task value lookup, pixel masking or automatic retry. Writer and Impress remain disabled by the existing ownership profile until their actual native app identity is independently observed.

The official [Collection API](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Collection.get_matches.html) distinguishes recursive traversal from direct-child queries. The [native state API](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/enum.StateType.html) specifies ancestor exposure for `SHOWING` and directs clients to avoid enumerating `MANAGES_DESCENDANTS`. The [Component point API](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Component.get_accessible_at_point.html) returns a native child containing a physical point. Current Context7 documentation was checked first; the GI-specific contract was verified against these primary GNOME sources.

Five offline fixtures exercise the actual reader functions for pre-enumeration pruning, explicit virtual branch deferral, bounded physical hit descent and foreign-process rejection, native focused versus selected state, and stale/cyclic hit rejection. These tests do not grant native qualification. V23, V24, V27, V28 and V29 sources and all historical failures remain preserved. The common guest factory must install the pinned V25 offline typelib before preparing the original task and bind the supplemental content to each newly attested base guest. The shared teacher, control, base and four checkpoint runtime remains gated until actual fresh native qualification is reopened independently.
