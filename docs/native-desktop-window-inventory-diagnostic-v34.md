# Physical and accessible window inventory

The actual V33 diagnostic observed an owned native frame and a center-hit parent frame with different bus/object identities. Both had the same process and native bus. The hit parent chain ended without the owned identity. This is not a proxy equality mismatch. It remains unknown whether there are two physical windows or a stale/split accessibility tree. Original refusal and zero qualification credit are preserved. The saved independent V33 audit SHA is `f6414ad7825f1c4d1e18e5746db57eab4742f9ee4d2e5a79235830bb77f09148`.

V34 is a separate read-only diagnostic. It inventories actual EWMH-managed X11 client IDs and their process ID, process UID, executable path/content hash, window-title hash, map state, WM class and absolute screen geometry. It inventories native top-level frames for the owned process and includes the original refused point's parent frame even when the application root does not advertise it. Native facts include real bus/object identity, role, parent identity, geometry, title hash, ACTIVE/VISIBLE/SHOWING/DEFUNCT/STALE/MODAL flags and hashes of the documented native attribute map. No document/cell/text/value interface is read. Only top-level frame names are read for the explicitly requested title hash.

Candidate association requires exact native PID/title/geometry plus the independently attested process UID/executable and a viewable physical client. Native geometry is considered only with VISIBLE/SHOWING and without stale/defunct state. There is no coordinate tolerance, containment heuristic, same-PID shortcut, arbitrary title matching or standard native XID attribute assumption. Zero or multiple exact candidates remain explicit. Even a unique candidate is diagnostic metadata, never actor ownership or native qualification. The code does not repair the old guard or reinterpret an earlier refusal.

The limits are 64 managed clients, 64 applications, 64 native frames and the unchanged 32-parent bound. Per-command read-only CLI calls have a five-second limit and 32 KiB output cap. The complete reviewed guest command retains the 45-second command/55-second request limit. Facts are saved in a bounded exclusive mode-0600 trusted guest journal before later queries; partial facts remain available on refusal. No cache mutation, GUI action, model call, restart or guest creation is implemented.

Context7 was checked first. The actual 2.44 GIR confirms the named native methods and state fields. Primary references are [GNOME Accessible.get_attributes](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Accessible.get_attributes.html), [Component.get_extents](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Component.get_extents.html), [EWMH client/active-window properties](https://specifications.freedesktop.org/wm/1.5/ar01s03.html), the [X.Org xwininfo manual](https://xorg.freedesktop.org/archive/X11R7.5/doc/man/man1/xwininfo.1.html) and [xdotool's primary manual](https://github.com/jordansissel/xdotool/blob/main/xdotool.pod). Absolute xwininfo coordinates are used; its derived `-geometry` string is not treated as ground truth. No relevant xdotool entry was available in Context7, so its primary manual was used.
