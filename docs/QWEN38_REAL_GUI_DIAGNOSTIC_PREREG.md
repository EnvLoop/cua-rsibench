# Preregistered Qwen3.8 real-GUI training diagnostic

**Status: source-only implementation; no paid diagnostic dispatch.** This is a separate development experiment, outside the four-researcher by six-cell full study. Its only eligible data are independently audited, public-**train** original Desktop GUI positive episodes under the common v0.6.6 screenshot/action contract. The existing [Impress source receipt](evidence/desktop-v066-public-train-sft-render-2026-09-28.md) verifies 18 image-bearing turns from one task. Earlier Calc and Writer positive controls lack per-action v0.6.6 observation/predispatch frame pairs and are ineligible. Neutral profile calibration has no actor actions or saved-state verdict and is also ineligible. New Calc and Writer train episodes must independently prove exact raw frames, applied actions, saved OOXML target/no-regression verification, guest identity, teardown, source rights, and train-only identity before their source adapters can be activated.

The [machine-readable preregistration](../runtime/qwen38-vision/real-gui-diagnostic-prereg-v1.json) is frozen before any diagnostic paid call. The source loader reopens a private manifest and allowlisted source adapter, verifies the published train-render receipt and current six-cell v0.6.6 ratification, and validates each observation/action pair. It requires **at least three distinct train tasks across Impress, Calc and Writer**, at least 24 training turns and a task-disjoint holdout of at least six turns. The holdout task combination is selected by a fixed SHA-256 seed over task identities and package hashes, with only turn counts and workflow coverage used as feasibility constraints. It never reads a selection or final identity. A within-one-task step holdout would measure mostly memorization and is not eligible for paid dispatch under this preregistration.

The fixed training schedule uses `Qwen/Qwen3.8-27B`, LoRA rank 8, seed 23, 64 Adam steps, batch size 2 and learning rate 0.0001. Deterministic epoch permutations cover every admitted training datum; optimizer state is saved after steps 16, 32, 48 and 64, with final sampler weights saved separately. The source-bound exact plan records rendered datum/prompt lengths, the 128 batch indexes, source and renderer hashes, estimated scheduled tokens and a nominal planning quote. **The quote is not a dollar stop or an account invoice.** The 64-step schedule, per-call timeouts, plan-specific one-shot intent and immutable public freeze bound this diagnostic run. Observed Tinker usage and provider invoice or credits must be audited separately. Diagnostic usage is never counted as one of the 24 uniform-budget official campaigns.

For each task-disjoint train-domain holdout screenshot, the base model and final LoRA checkpoint receive the **same** Qwen multimodal prompt, temperature 0, seed 23 and 128-token ceiling. Their order alternates by holdout turn. The strict v0.6.6 parser independently checks whether each response is a valid current-frame GUI action, whether its action type agrees with the scripted reference, and whether its entire action payload exactly agrees. Action-type and exact-payload counts are additionally reported for **non-wait** reference turns so trivial delays cannot dominate the comparison. Paired gain/loss counts are reported without private text, screenshots, task IDs or checkpoint URI. These are teacher-forced next-action diagnostics. They are **not** interactive task completion, a selection score, a final result, or evidence of general computer-use improvement.

The [one-shot runner](../src/cursibench/qwen38_real_gui_diagnostic_run_v1.py) refuses paid work until it can rebuild the exact private plan, retrieve an exact freeze witness from an immutable public Git commit, recheck the pinned clean Qwen runtime and toy API evidence, confirm the active process uses the dedicated root venv with Hugging Face rendering offline, and find a new plan-specific paid-intent slot. Every Tinker operation gets an fsynced, hash-chained private request and intent before invocation; returned bytes are saved separately. An interruption or ambiguous provider response is never automatically replayed, and a second run directory cannot reuse the same plan. The witness file does not yet exist, so the runner is intentionally closed. The [CLI](../tools/run_qwen38_real_gui_diagnostic_v1.py) supports source preview, offline exact-plan preparation, paid run after freeze, and read-only journal status.

The runner records scheduled training tokens, rendered sampling-prompt tokens and observed sample-output tokens separately from provider billing. Once the provider's hourly usage data is available, the read-only [usage reducer](../src/cursibench/qwen38_real_gui_diagnostic_usage_v1.py) and [audit CLI](../tools/audit_qwen38_real_gui_diagnostic_usage_v1.py) match events to the diagnostic's `run_id` metadata, report provider-reported token counts and a source-bound published-rate subtotal, and preserve raw organization/session records privately. Checkpoint/storage events, billing delay, credits and discounts remain visible limits. The subtotal is **not an invoice**; a provider invoice or account statement must be reviewed separately before claiming actual dollars spent. No arbitrary dollar quote stops the preregistered 64-step diagnostic.

The current read-only preview revalidated the one real Impress trajectory and returned `blocked_before_any_paid_call` because Calc/Writer v0.6.6 train episodes are not yet available. All current runner/partition tests use synthetic episodes or fake provider callbacks and make zero Tinker calls. The formal study's 20 selection tasks per cell and all 100 final tasks per cell remain untouched; an authentic training-effect claim on original software requires those later matched, frozen study evaluations. Tinker method signatures were checked against the pinned local 0.30.0 SDK and the official [TrainingClient](https://tinker-docs.thinkingmachines.ai/tinker/api-reference/trainingclient/) and [weights-management](https://tinker-docs.thinkingmachines.ai/tutorials/core-concepts/weights/) references. Context7 documentation lookup reached its monthly quota, so the local pinned SDK and primary documentation were used for this implementation.
