# Pre-result action-source freeze for evaluator controls

This amendment separates **source-code identity** from **live application acceptance** before any full-study model outcome. The six-cell static [adapter ledger](evidence/full-study-v066-six-cell-static-2026-09-28-readiness.md) had required a live train or selection smoke in every application before recording a common v0.6.6 ratification. That sequencing held the 300 native Desktop evaluator controls behind unrelated Office-account and self-hosted runtime work. It did not protect hidden model outcomes: none exists. The amended sequence first freezes the exact common action/parser/renderer sources and six adapter source hashes, then permits evaluator-only native GUI qualification under those bytes. Campaign dispatch and official task admission still require per-cell live smoke, source/runtime/rights/budget evidence, a separate full six-cell pre-campaign witness, and all 600 individually qualified tasks.

The [ratification builder](../tools/ratify_v066_action_source_for_controls_v1.py) reopens the dated static ledger and hashes every adapter dependency rather than accepting caller-supplied hashes. Its private record uses the existing `cua-six-cell-action-profile-v066-ratification-v1` schema so the Desktop v0.6.6 control lane can bind the same source bytes. The public receipt publishes only hashes and explicitly reports zero admissions, campaigns, and official model results. A separate $60 E2B full-lease reservation and a first-task evaluator control are reviewed before dispatching the remaining Desktop task trios. The 300 planned sandboxes are a cost ceiling, not a provider invoice.

If any common source or cell adapter changes before the full-study pre-campaign witness, the code-only ratification is superseded. Desktop controls bound to its old digest remain development evidence; they may enter the official denominator only if an independent audit proves byte-identical source/runtime/verifier bindings and the later six-cell acceptance gate explicitly adopts that digest. Otherwise the affected controls must be rerun. No model actor receives held-out instructions or gold during evaluator qualification, and no historical v0.6.4/v0.6.5 GUI control is relabeled v0.6.6.
