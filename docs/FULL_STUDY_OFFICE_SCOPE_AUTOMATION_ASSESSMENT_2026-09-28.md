# Office owner-side sharing at study scale

**Pre-result assessment; no live Graph write was dispatched.** Microsoft Graph v1.0 documents the owner-controlled operations needed to remove the manual *sharing* bottleneck on a non-root OneDrive item. A delegated personal-account token with `Files.ReadWrite` may [invite one recipient](https://learn.microsoft.com/en-us/graph/api/driveitem-invite?view=graph-rest-1.0) with `roles:["write"]`, `requireSignIn:true`, and `sendInvitation:false`. The response includes a permission ID. The owner can later [delete that exact permission ID](https://learn.microsoft.com/en-us/graph/api/permission-delete?view=graph-rest-1.0), then independently [list effective permissions](https://learn.microsoft.com/en-us/graph/api/driveitem-list-permissions?view=graph-rest-1.0). The list can retain owner and inherited entries after deletion; requiring `value == []` is incorrect. The current PowerPoint worker instead binds the prior ID and actor email from its private one-file ACL snapshot, rejects that ID or actor identity if still present, rejects broad or unidentified links, and tolerates identified owner/inherited entries.

This supports an evaluator-only controller design: create a new task file under an unshared owner folder; verify its seed bytes and exact drive/item identity; grant one specific actor; read back the new permission ID and require the existing single-file ACL and sentinel-denial checks; let the actor work through Office GUI only; revoke that ID; then read back effective permissions before sharing the next file. Graph creation/revocation is **evaluator fixture management**, never an actor action or model tool. The same sequence applies to a fresh neutral reset copy and to Excel. Existing Graph v1.0 [small-file upload](https://learn.microsoft.com/en-us/onedrive/developer/rest-api/api/driveitem_post_content?view=odsp-graph-online) or asynchronous [driveItem copy](https://learn.microsoft.com/en-us/graph/api/driveitem-copy?view=graph-rest-1.0) could provision those copies, but each resulting item, contents, parent ACL, and permission must be independently read back before use.

The protocol is **not ready for unattended publication-scale dispatch**. The current account has not provided a verified delegated owner token or consented `Files.ReadWrite` scope to this worker; the actual personal OneDrive behavior of silent specific-person invitation, permission deletion, and actor visibility is untested. The E2B Office actor also currently requires manual sign-in for each new desktop lease. Automating owner-side Graph grants alone does not solve thousands of interactive sign-ins or prove the six-cell action/profile and task admissions. A bounded train-only live pilot must establish token identity/scope, one-file edit, sentinel denial, exact saved-file download, revocation, fresh reset, and ledger billing before this control path can replace operator-prepared receipts. Until then, missing Graph write credentials or live evidence is a dispatch blocker, not an invitation to weaken ACL checks.
