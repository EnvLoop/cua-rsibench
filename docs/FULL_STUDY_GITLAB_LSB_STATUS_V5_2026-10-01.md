# Documented LSB down status and independent rollback

V4 successfully stopped Sidekiq while PostgreSQL and Redis remained running, but its status reader rejected native exit code 3. Its restoration callback reused that reader and failed before restoring the deliberately stopped service. The failed attempt remains consumed and unqualified. Root restored Sidekiq once in a separate recovery receipt and independently verified all seven critical services, the same original identity, exact SQL baseline and 198 before/restored Git-tree records. No old failure or recovery is promoted to trial/task credit.

The installed `omnibus-ctl` 0.6.12 sums the init-service exit codes. Its source SHA is `50d421e29a29c0671217772556cc542b91b95f0dfe365015e05ce008b96e2bfc`. The Sidekiq init entry points to the runit binary with SHA `9199e99b8106b7acd57f2038b97b357264d8fe746f3268f7a82d16e3704e756b`. When invoked through a service basename, [the official runit manual](https://smarden.org/runit/sv.8) defines status 3 as down and status 4 as unknown. The actual retained V4 before-status is 0 with all services running; its after-status is 3 with only Sidekiq down and empty stderr. Context7 had no matching runit documentation; the primary manual supplies the exit-code boundary.

V5 accepts status 0 only with valid known rows, a complete critical-service roster and no down service. It accepts status 3 only when the sole listed down service is Sidekiq and every other critical service remains running. It preserves the exact raw return code, stdout and stderr. Exit 1, unknown 4, foreign services, daemon/context errors, malformed/empty output, missing critical services, and another down critical service fail. Down is a physical lifecycle state; it is never reported as healthy or as a configuration disable.

The rollback callback now checks the preserved identity and runs independently of the pre-restoration status decoder. If the original container never stopped and our known Sidekiq stop was attempted, a reader exception cannot suppress the single documented start used to undo that lifecycle action. The original baseline restoration then runs. A post-restoration reader error still makes the attempt fail, while preserving its restoration snapshot and exit metadata. Identity changes never authorize a blind start. This is rollback, not a trial retry.

V4 source and all earlier source bytes, consumed intents, native raw records and recovery evidence remain unchanged. The same ordered stop, strict Docker process exit 0, no-retry policy, 300-second stop allowance, SVWAIT 60, readiness 900, image, hardware, suffix, service configuration, seeds and task data remain in force. The new source plan needs independent exact review before any new three-clone run. Source tests include an opt-in replay of the actual private exit-3 streams; those streams are never copied into public fixtures. Historical/task/model credit remains zero.
