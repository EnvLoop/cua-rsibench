# Excel Web SEC teacher episode worker

**Status: prospective train-only implementation, zero live episodes and zero official full-study campaigns.** The six-cell v0.6.6 ratification, authenticated owner Graph readback, Excel actor sign-in, and Excel-web admission remain outstanding. The offline tests below do not admit a final task or establish a model score.

`tools/office_web_excel_teacher_worker_v1.py` implements the shared `collect_train_batch` cell-worker interface for an original **SEC integrated training case** in Excel for the web. It checks a frozen campaign and common v0.6.6 action profile before any provider reservation. A private one-case manifest must declare `train_candidate`; the actor `task.private.json` and `actor.xlsx` must match the campaign's train task identity and byte hashes. A separate evaluator-only `reference.xlsx` must pass the original filing-pinned SEC verifier while the unrepaired actor workbook fails. The current worker covers this integrated SEC training workflow; it does not yet cover every Excel train workflow or qualify the 100 final candidates.

The teacher can see only the actor instruction and current Excel screenshot. Mouse and keyboard actions are validated against the current frame and sent to the real Excel web GUI inside a bounded E2B Desktop lease. A distinct actor Microsoft account receives one specific-person write permission to one train workbook; a recent owner-side permission snapshot, assigned-file edit probe, sentinel denial, and parent-folder nonsharing check are required before the first model action. Gold/reference files, the SEC case, owner Graph token, and cloud item IDs stay evaluator-only.

An evaluator with delegated owner access then double-downloads the exact OneDrive `.xlsx`, requiring stable drive/item/name/MIME/size/eTag and identical bytes. The independent `sec_excel_factory/verify_integrated_candidate.py` runs in a separate process. It requires at least 20 formula targets, checks financial numeric outputs under the original SEC filing facts plus **two** source/scenario counterfactual profiles, and rejects changes to non-target cells and workbook structure. This does not claim that Excel's native recalculation engine refreshed every cached value; the evaluator checks caches when present and independently recomputes dependencies. The source, verifier, OOXML reader, Graph reader, E2B runner, GUI adapter, and inherited Office action loop are all hash-bound in the private binding and six-cell ratification.

After the actor lease terminates, the owner removes the exact actor permission ID. Graph must show that ID and actor identity absent, with no broad or unidentified sharing link; owner and unrelated inherited permissions may remain. A second, distinct E2B desktop opens a separate neutral workbook with its own one-file actor scope. Its double-downloaded bytes must match the actor seed **semantically across every sheet, formula, numeric value, merged/table structure, and cell**. The reset lease must terminate and its actor grant must also be removed before the worker writes an admitted teacher episode receipt. Both E2B leases and all owner readbacks use the campaign dollar ledger; uncertain requests retain their reservation and are not silently repeated.

`prepare_private_binding(session, task=..., task_path=..., cases_path=..., case_id=..., reference_path=..., actor_item=..., reset_item=..., owner_email=..., actor_email=..., out_path=...)` creates a mode-0600, source-hash-bound private binding without a provider call. Construct `OfficeExcelTeacherWorker(session, binding_path)` and pass it to `collect_train_batch(session, round_index, train_context_path, out_dir, worker)`; the returned private manifest and in-memory Qwen3.8 v0.6.6 datums feed the separately budgeted Tinker SFT step. Each new E2B session needs manual actor login and freshly reviewed `run.private.json`/`actor-scope.private.json` files. No credentials or hidden task IDs belong in the public repository.

The owner-side Graph API can in principle automate specific-person invite/revoke and file-copy fixture management under a verified delegated `Files.ReadWrite` scope, as described in the [scope automation assessment](FULL_STUDY_OFFICE_SCOPE_AUTOMATION_ASSESSMENT_2026-09-28.md). That permission scope and the personal-account behavior have not been tested here, and the current E2B actor login remains manual. At publication scale those are operational blockers. The current evidence is fake-provider tests of exact XLSX owner readback, owner/inherited permission semantics, train/final isolation, formula and non-target numeric rejection, stale frames, ACL failure cleanup, fresh reset drift, private binding, and the shared episode receipt contract. No live Graph, Office, E2B, teacher, or Tinker call was made for this worker.
