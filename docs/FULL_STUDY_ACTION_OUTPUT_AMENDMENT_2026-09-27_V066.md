# Proposed pre-result common GUI action amendment v0.6.6 — 2026-09-27

**Status: proposed, not ratified.** No official final model attempt, researcher campaign, or Desktop admission has occurred. The existing v0.6.5 proposal addressed formatting errors observed on training tasks. A separate [read-only Desktop admission preflight](evidence/native-wdi-v065-final-admission-preflight-2026-09-27.md) then found a material action-coverage problem in evaluator-owned final controls. All 100 historical positive and near-miss scripts used GUI typing into the current focus without a target; 25 Impress cases used native double-click; 25 Writer cases used explicit navigation/find chords outside the v0.6.5 allowlist. Every old action transcript also lacks a per-action frame record. Those saved-artifact controls remain valid developmental solvability evidence, but **none is retrospectively relabeled as a v0.6.5 or v0.6.6 control**.

The proposed [full-action validator](../src/cursibench/scale_action_contract_v066.py) and [minimal model-output adapter](../src/cursibench/scale_action_output_v066.py) add only three cell-neutral GUI primitives:

1. `double_click {target}` uses the same current screenshot, pixel bounds, or visible enabled control ref as `click`. The trusted adapter dispatches an actual native double-click.
2. `key {key}` additionally allows exactly `Control+F`, `Control+H`, `Control+End`, and `Shift+End`. All other unapproved chords still fail. Existing target, memory, task, frame, step, and expiry checks remain.
3. `type {text,mode:"insert"}` may omit `target` to type into the currently focused GUI control. This is a keyboard operation; the trusted adapter must **not synthesize a click**. Targetless `fill`, empty text, text beyond the frozen 8,192-byte default, and extra fields fail. The actor still receives a current screenshot before each turn and the adapter rechecks the physical frame immediately before dispatch.

The shared trusted action version stays `scale-computer-use-v0.6`; the proposed profile is separately tagged `scale-action-profile-v0.6.6`. Exactly one JSON object, the v0.6.5 whole-response fence and unambiguous `action` alias rules, and all old GUI action shapes are retained. No selector, browser navigation, shell, filesystem, document API, network, or arbitrary keyboard shortcut is added. Tests check old-action equivalence, current-frame and expiry rejection, target bounds, stale or invented refs, malformed JSON, unapproved chords, and the Desktop dispatch mapping. The source bytes and receipts of earlier versions remain unchanged.

The [offline final control plan](evidence/native-wdi-v066-control-rerun-plan-2026-09-27.json) compiles all **100 positive and 100 near-miss** evaluator scripts into the proposed grammar. Each prospective Calc or Impress run needs 25 actions and each Writer run 53 after waits are split to the existing 2-second ceiling, below the 90-action limit. This is **only syntactic feasibility against a synthetic frame**; it creates no E2B sandbox or per-ID v0.6.6 GUI proof. The old 100 trios, 100 fair-scorer positives and 100 rejected near-misses are preserved, while the v0.6.6 live GUI trio and official counts remain **0/100**.

The later [bounded real train-only smoke](evidence/native-wdi-v066-train-primitive-live-2026-09-27.md) exercised a public Impress fixture in five fresh, guest-attested E2B Desktop sandboxes. It preserved two correct physical-frame rejections and one E2B `ReadError`; two attempts saved and independently verified the training PPTX. One successful attempt applied native double-click, focused insertion, and all four new explicit chords under the proposed parser/dispatcher. Its raw observation frames and pre-dispatch hashes were recorded; subsequent failed attempts also retained raw pre-dispatch frames. No hidden final package or model was used, so the final-ID prospective trio count remains zero.

**Adoption condition.** Before model selection, researcher training, or hidden final scoring, all six cells must ratify one identical v0.6.6 prompt/parser/full-validator profile and bind its exact source, renderer, teacher, student, checkpoint, and runner hashes in the pre-campaign manifest. Each cell adapter must implement the same new GUI semantics or fail explicitly on unsupported operations; the common model cannot receive cell-specific undocumented syntax. Base and selected checkpoints must use the same profile. A bounded train/selection-only live smoke should confirm the Desktop adapter and the other five application adapters without inspecting hidden final outcomes.

A later [reproducible proposed source bundle and six-cell adapter ledger](evidence/full-study-v066-action-profile-2026-09-27-readiness.md) binds the shared v0.6.6 code and prompt bytes. Synthetic parser/dispatcher tests cover PowerPoint-web, Excel-web, Desktop, Odoo and Magento; GitLab is separately pending. These local tests neither wire the historical application runners to v0.6.6 nor supply the required source-bound live train smokes. The linked bundle is **not** the pre-campaign ratification or a replacement for the historical v0.6.5 Tinker receipt.

For Desktop admission, fresh prospective evaluator controls must be rerun under this frozen profile: **100 positive, 100 near-miss, and 100 fresh cold-reset sandboxes**. Every sandbox must attest the scoped guest-content identity and provider shape before document staging, bind its task-specific neutral LibreOffice profile, and record per-action observation screenshot/frame and immediate pre-dispatch physical-frame check. Positive and negative saves must be independently read back and evaluated by the already frozen fair OOXML scorer; the cold sandbox must restore the original input. Old receipts cannot supply missing frame or guest proofs. An uncertain create/teardown consumes its full budget reserve and blocks that task until reconciled. The existing `$40` Desktop development lane has only `$0.8389` of conservative full-lease headroom. At 600-second leases and the conservative `$1/hour` planning rate, 300 new sandboxes require **$50** in a separately bounded lane, or **$60** with a maximum 60-sandbox retry/uncertainty allowance; provider-billed USD remains unknown. No such campaign is dispatched by this amendment.

The `cua-final-cell-v0.6` qualified manifest stays absent. Desktop and six-cell official final admissions, final model results, and researcher campaigns remain **zero** until all per-ID, action, runtime, source-rights, budget, and cross-cell gates pass.
