# Odoo train attachment-route calibration, additive v5

The v4 train-only attempt reached an original Odoo Community purchase RFQ, then stopped on its native **Attach files** button. Its [independent terminal audit](evidence/odoo-v066-train-attachment-route-v4-terminal-2026-09-29.md) confirms three completed GUI actions, one durable failed-action intent, unchanged baseline/restored SQL, an exact full filestore reset, a released lease and cold services. The source PDF link and viewer were never reached. V4 remains terminal under its existing run ID.

The failure exposed a Python method-signature collision. The train PDF-link subclass used `_record_final(observation, stage, index, raw, classification)`, shadowing the v6 RFQ dispatch method `_record_final(observation, *, sample, png, classification)` for every non-link click. V5 keeps the v6 method inherited unchanged and renames only the train link's local writer to `_record_attachment_final`. The visible-link identity, frame, URL, target and two-final-frame guards remain the same. The new adapter is source-neutral code but is dispatched only by this train-only calibration runner.

V5 has a distinct run directory (`attachment-route-train-pilot-20260929-03`) and a fresh private 128-bit nonce. The [public source freeze](evidence/odoo-v066-attachment-train-source-freeze-v5-2026-09-29.json) binds the private freeze hash, nonce hash, accepted prior train audit and 26 source files. Offline freeze verification passed with both cases in the train partition and the v5 run directory absent. Fourteen targeted tests passed, including a direct regression for the exact keyword-only parent call that failed in v4 and the link's positive/negative frame guards. No v5 Docker, GUI or model action has been executed at this stage.

After root review, a single v5 train-only GUI run may exercise the frozen package. On success, a separate reviewer must inspect the source viewer screenshot and rendered source PDF, exact action/guard records, positive and wrong-object saved SQL and full filestore manifests, cold reset and lease/service cleanup before publishing a train-control receipt.
