# Original Office neutral lifecycle pilot v4

V4 preserves the v3 sources. It uses only the documented native download `path({timeoutMs})` method. The path basename must be the exact selected document filename or its standard browser ` (n)` collision suffix. Different documents, other extensions, folder ZIPs and unrecognized collision syntax are refused. The private receipt retains the actual basename/path hash and records that no HTTP-suggested filename was observed. Office ZIP member directory, local headers, boundaries and required root/main parts are checked; independent Python package parsing/scoring remains authoritative for document content.

`office_owned_folder_cua_pump_v4.mjs` uses the V4 lifecycle and download checker with V3 host/principal/geometry code. Freeze `officeV4SourceHashes()` in both private binding and source admission. All V2/V3 byte histories remain unchanged.

`office_neutral_lifecycle_pilot_v4.py` prepares and checks a single TRAIN-only native lifecycle. Run requires an explicit reviewed permit. It opens a fresh owned source document, observes a current cropped frame, dispatches an explicitly synthetic neutral finish through the shared native guard, double-downloads/scorers the saved artifact, closes/removes only its owned copy and makes a distinct fresh reset. It never invokes a model or provider sampler. A strict task score is reported separately from neutral source equivalence. This control does not grant generic student verification, formal admission or native qualification.

The private profile/binding/package scaffold is source-only. Root must observe and approve the exact Delete/confirmation recipe, passive account controls, parent folder-card count, clip and tab scope. Preparation never writes unconditional qualification. The Chrome file-URL permission preflight is a separate user-controlled application setting; a rejected upload is not an upload or lifecycle result.

## Root execution order

After importing the source and approving the exact private profile, bind the reviewed profile hash in a fresh config:

```bash
PYTHONPATH=.:src "$TASK_PYTHON" -m tools.office_neutral_lifecycle_pilot_v4 prepare \
 --repo-root "$TASK_REPO" --package-descriptor "$TASK_PACKAGE_DESCRIPTOR" --package-root "$TASK_PACKAGE_ROOT" \
 --binding "$TASK_BINDING" --profile "$TASK_PROFILE" --output "$TASK_FRESH_OUTPUT" --config "$TASK_CONFIG"
```

The source-only check is:

```bash
PYTHONPATH=.:src "$TASK_PYTHON" -m tools.office_neutral_lifecycle_pilot_v4 check --config "$TASK_CONFIG"
```

Root's permit schema is `office-neutral-lifecycle-pilot-permit-v4`, with the exact config SHA, `root_source_reviewed:true`, `native_execution_authorized:true`, `synthetic_neutral_finish_only:true`, `model_calls_authorized:0` and `native_lifecycle_qualified:false`. Only after explicit native authorization:

```bash
PYTHONPATH=.:src "$TASK_PYTHON" -m tools.office_neutral_lifecycle_pilot_v4 run \
 --config "$TASK_CONFIG" --permit "$TASK_PERMIT" --enable-native
```

The terminal writes `source-admission.private.json` and creates `operation-spool.private` beneath the fresh output. Root then imports the V4 CUA pump, reads that actual admission plus the frozen binding/profile, and constructs it with the current native folder tab/browser, private evidence root and actual document-tab inventory function. Poll one `pumpOnce()` at a time while the terminal waits. Existing operation claims cannot replay, and uncertainty preserves evidence/account lease rather than retrying. No source task drives the GUI.
