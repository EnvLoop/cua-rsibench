# Odoo Community v0.6.6 twenty-task selection worker

**Status: implemented and fake-provider tested; no live selection execution.** The [worker](../enterprise_fallback/odoo18/selection_worker_v066.py) accepts only the five-field receipt returned by `CampaignSession.start_selection_attempt`, the private Tinker sampler checkpoint path whose SHA-256 equals that receipt, and the byte-exact frozen Qwen training configuration. It receives no train or hidden-final task view. An evaluator-owned private Odoo `selection` worker supplies only the 20 matching case instructions after the manifest and package hashes pass; the model sees current screenshots, visible controls and the task instruction, never SQL, gold or credentials.

Live execution defaults to disabled. Before any local service or Tinker reservation, the worker requires the real six-cell v0.6.6 ratification, current Odoo adapter/runtime/verifier source hashes, a mode-0600 private local cost authority and the pinned Qwen renderer. The private Odoo selection directory and its task packages must pass mode and source checks. The earlier Odoo training smoke and training teacher worker are separate evidence; neither is a selection model result.

The evaluator calls `session.dispatch_paid` twice after `start_selection_attempt`: once with category `storage_application` to reserve a bounded self-hosted Odoo service lease, then once with category `tinker` for the full 20-task, 90-action-per-task upper token envelope. The local reservation is a **nominal opportunity-cost ceiling**, with measured wall time and `provider_invoice_usd: null`; it is never called an E2B lease or provider invoice. Both paid requests bind the exact selection-identity hash; the Tinker request also binds the checkpoint and frozen student configuration. A Tinker batch paid result binds the 20-row selection result, full task ledger, usage, timeout and local-runtime receipts. External provider billing still requires separate reconciliation.

In the real backend, one pinned Qwen sampler checkpoint serves 20 tasks. Each task starts from an exact PostgreSQL and physical-filestore restore and an unsolved independent baseline, runs only v0.6.6 current-frame Playwright GUI actions in original Odoo Community 18.0, then reloads the browser and uses the independent SELECT-only evaluator and protected-source checks. The worker saves mode-0600 frames, action traces, durable sample journal, actor-saved SQL snapshot, verifier result, usage and reset receipt. Another exact cold restore follows every task and the complete batch; the original service state is restored at exit. A completed but invalid model action or an exhausted action/wall budget may yield a valid task score of zero. Provider uncertainty, a stale physical frame, a changed artifact or an inexact reset invalidates the **whole** selection attempt and preserves private failure/timeout evidence without automatic replay.

On complete success, `run_selection` returns an exact `cua-full-study-selection-saved-result-v1` for all 20 bound IDs, the two paid attempt IDs and mode-0600 usage/timeout/local-runtime references. It also returns the private `task-ledger.private.json` path and SHA-256. The ledger has schema `envloop-odoo-v066-selection-task-ledger-v1`; each ordered row binds task and package IDs, the checkpoint hash, score, saved-state/verifier/reset hashes, action and frame-manifest hashes, sample-usage hash and counts. A caller can pass `result` and `paid_attempt_ids` to `session.record_selection_scored`; an invalid return instead supplies a private evaluator-receipt hash for `record_selection_invalid`. These registrations and billing reconciliation remain evaluator-controlled.

Eight synthetic worker tests cover a full 20-case result, checkpoint/config tampering, cost-authority privacy, provider uncertainty, changed saved state, inexact local reset and pre-freeze refusal. They patch the service/sampler boundary and make **zero** Docker, Tinker, E2B or final-task calls. The [six-cell environment mapping](evidence/full-study-selection-environment-classes-2026-09-28.json) and dispatcher have separate tests. A live run remains contingent on the actual six-cell pre-campaign freeze, cost-authority binding, restricted selection worker preflight, real Tinker usage/invoice reconciliation and independent review of every per-task artifact. Official selection/model/final counts remain zero for this implementation.
