# Magento Open Source v0.6.6 train teacher episode boundary

**Status: source-bound worker interface and fake GUI/evaluator tests only.** The [worker](../tools/magento_teacher_episode_worker_v066.py) accepts the frozen campaign teacher API `run_episode(task, out_dir, sample_teacher, dispatch_e2b)`. It requires one exact private task from the 20-case **train** partition, binds its package SHA-256 and visible instruction, and rejects an identity in selection or final. Its actor loop uses the original Magento admin screenshot, visible controls, the shared v0.6.6 action parser and the pinned Playwright GUI dispatcher. Each paid teacher result is checked against the same physical frame before GUI dispatch; frame PNGs and the teacher action trace are retained privately. The independent `magento_catalog_factory.verify.score_saved_state` reads persisted SQL and search state, verifies the native price save and rejects source, comparator, other-catalog, business or unrelated-search regression.

The worker prepares the exact episode files expected by `collect_train_batch`: mode-0600 frames, canonical `actions.private.json`, saved SQL/search artifact and verifier receipt, baseline and restored semantic snapshots, and a fresh-clone reset receipt. The raw pre/post snapshots remain separate private artifacts even when the only accepted reset difference is Magento's explicitly checked target low-stock timestamp. Admission requires a distinct app and search clone for reset, no host mounts, both pairs removed, a correct saved-state score of 1, and a final model `finish` action. Failed or uncertain episodes retain a private failure record and never produce training data.

Magento is a self-hosted original-software cell. The evaluator must pass a frozen `storage_application` dispatch callback and a private nominal local-cost authority. The callback reserves its full service envelope before opening a clone; its receipt says `provider_invoice_usd: null`. `dispatch_e2b` is never called. The campaign teacher adapter separately reserves each Sol multimodal request before the provider call. A local planning cost is not a provider invoice, and neither the fake tests nor this module reconcile real billing.

**The dedicated clone lifecycle is implemented offline but not live-qualified.** The [new launcher and resetter](../tools/magento_dedicated_train_lane_v066.py) uses two app/search pairs with names, loopback ports and a network disjoint from the running v2 100-case evaluator. A read-only Docker identity check refuses to create either pair while either evaluator container still exists. It pins the original Magento and native search images, disables cron autostart before supervisor, verifies the 181-document source search index and zero price-index drift, uses read-only SQL/search snapshots for scoring, then removes the actor's pair by exact container identity and seeds the same case into a second fresh pair for physical reset. Every mutating Docker command has a durable one-shot intent and outcome; a timeout or partial cleanup is retained for operator audit without automatic replay. Failed process output, when present, is kept mode-0600 with the private journal. The original three v2 evaluator files were not edited.

The worker's default `enable_live=False` remains unchanged. Its source-bound live gate now also requires a mode-0600 independent **training-only** positive **1**, wrong-variant **0**, fresh-clone-reset receipt, exact launcher/verifier hashes, disjoint lane names/ports/network, pinned images, role-scoped credentials and a private local cost authority. None of those completed live-smoke receipts exists yet. The launcher code has **not** issued Docker commands or authenticated in Magento; its real startup and cleanup behavior must be tested only after the v2 evaluator lane is free. This is a material remaining gap, not a live teacher episode.

The nine worker tests and nine new fake-process/Playwright lane tests cover `collect_train_batch`, v0.6.6 GUI dispatch, saved-state/no-regression scoring, source-bound live-gate acceptance and refusal, disjoint clone startup, evaluator-container overlap refusal, cron-before-supervisor ordering, independent readback, distinct fresh-pair reset, actor-interruption cleanup, changed or unexpectedly exited containers, private failed-process diagnostics and no replay after a stop timeout. They make **zero** real Docker, Magento, E2B, Sol or Tinker calls. The earlier [worker-only offline receipt](evidence/magento-v066-teacher-worker-offline-2026-09-28.json) remains historical; the [dedicated-lane offline receipt](evidence/magento-v066-dedicated-train-lane-offline-2026-09-28.json) binds the revised source. There are no official model outcomes, final admissions or researcher campaigns from this work.
