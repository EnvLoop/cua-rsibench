# GitLab pre-result failure recovery and ordered source replacement

**Status: prospective development-control protocol.** This amendment precedes any official final identity, student-model outcome, or researcher campaign. It does not turn the GitLab candidate inventory into an admitted benchmark cell. The initial native-GUI controls and their failures remain in the private append-only ledger and in the public aggregate denominator.

## Frozen reserve commitment

The [machine-readable commitment](evidence/gitlab-pre-result-recovery-queue-2026-09-28.json) fixes a FIFO queue of **five complete project source families, five tasks each**, before the original GUI-control sweep or any requalification yields a final result. The ordered private queue is SHA-256 `e74c499312c9a3c8aa10964edfafd19f11dc7152c75ffa44e272b77a921dcdfd`. Its input 31-project private world is SHA-256 `8a815883423f48960bd28ac4ba448578a48d19a7c1fdb086f4c914ec2b412085`. The complete CISA KEV catalog is pinned to commit `203fa463` and SHA-256 `39099ffcf82c3f183fa6f7326900a6d82731517b2edb5cecde06dee6e04289d1`; the source facts remain CC0, while all internal business records remain explicitly synthetic.

The reserve builder ranks unused vendor identities by a seed-keyed HMAC, then ranks CVEs within each selected vendor. It takes the first 20 previously unused vendors, groups their chosen advisories four at a time, and generates project indices 32–36 in that order. The private queue is committed in ignored mode-`0600` evaluator storage. Project paths, CVEs, vendor identities, assets, principal names, task IDs, prompts, source-to-project mapping, and gold are absent from the public commitment. The code checks complete disjointness against all 31 existing projects for CVE, vendor, project path, source family, asset, principal, and task identity. Every replacement has the same five causal workflow families as an original final project. The five-family cap is fixed; the evaluator cannot keep drawing from the catalog until enough easy cases pass.

## First-attempt classification and one controlled requalification

Complete all **100 original active candidate IDs** first. Freeze a copy of the private index and verify its 100 first-attempt records against the hash-chained failure ledger. Publish the original attempted/pass/invalid counts and ledger head without identifiers. A 1/0/0 or 0/0/1 trio is a deterministic GUI-control miss, even when one of its positives saved correctly. An interrupted driver, unhealthy fresh clone, or unverified reset is an infrastructure-invalid qualification attempt, never a student-model failure.

Each failed original ID is eligible for **at most one** fresh-clone, complete 1/0/1 requalification with three independently verified cold resets. A deterministic miss requires a frozen, workflow-generic controller revision and a hash-bound training-partition receipt showing visible save completion, reload persistence, independent readback, near miss, and reset. The revision must apply to the workflow rather than branching on a task ID or private answer. If that evidence is absent, retire the affected five-task project family immediately. Infrastructure-invalid IDs may receive one fresh-clone requalification without relabeling the original attempt. The new `--retry-failed` path refuses to run without a mode-`0600` private resolution plan binding the original 100-ID roster, first-attempt records, ledger head, eligible IDs, and any generic training evidence. It refuses a third attempt or a changed first attempt. Every new failure is appended to the same ledger; a later pass never removes the first failure.

The milestone controller now waits for the native save spinner to clear and requires both issue-to-milestone links to survive a page reload, with up to three identical bounded attempts per issue. `tools/probe_gitlab_milestone_save_train_v1.py` is a train-project-only 1/0/1 and cold-reset calibration using independent PostgreSQL/Git readback. Its local unit tests cover correct, wrong-date, missing-link, and unrelated-change cases. **The live training probe has not been run at this amendment**; this code change does not authorize regrading the preserved 0/0/1 original attempt. The live probe must run after the original serial sweep ends, with no competing GitLab worker, and its receipt/operator hash must be frozen before one-time requalification. The earlier due-date save calibration is separately retained and likewise needs an exact revision/receipt binding for the 1/0/0 case.

After both training receipts are reviewed, write a private mode-`0600` JSON mapping with schema `envloop-gitlab-generic-fix-evidence-map-v1` and a `workflows` object mapping each eligible deterministic workflow name to its exact training receipt SHA-256. `python3 -m gitlab_world.pre_result_recovery freeze-resolution --generic-fix-evidence-path <private-map>` then verifies the complete original index against the hash-chained ledger and writes a mode-`0600` resolution; its standard output contains only aggregate counts and digests. An intentionally empty `workflows` map retires deterministic failures immediately. The resolution is exclusive and cannot be overwritten after a retry result.

## Whole-family retirement and FIFO replacement

If a controlled requalification fails, quarantine the **entire five-task source/project family**, including any siblings that passed their first GUI trios. Deduplicate by source family, order retired families by earliest original failure-ledger sequence, and assign reserve projects 1, 2, and so on in the previously committed FIFO order. A failed replacement family is likewise retired as a whole, consumes one of the five reserve positions, and remains in the attrition audit. No single failed variant may be swapped out, and no replacement is chosen from model outcomes. Exceeding five consumed replacements stops the GitLab cell below the requested denominator and requires a new public preregistration rather than an unreported refill.

The resulting inventory must still contain **20 active project source families × five tasks = 100 identities** and exactly 20 selection tasks, with the original train/selection/final project, CVE, vendor, asset, principal and template boundaries independently rechecked. For each new project, bootstrap the real GitLab CE 18.5 fixture, freeze a new immutable-volume lowerdir and independent PostgreSQL/Git baseline, recheck the non-admin partition ACLs, and run all five native-GUI positive/negative/repeated-positive controls plus three cold resets per ID. A prospective roster count is not a GUI pass. The original 100-ID first-attempt denominator, every failed family, every reserve consumption, each bootstrap/reset error, and all costs remain reportable even if the final 100 eventually qualify.
