# GitLab CE v0.6.6 selection worker

**Status: implemented and tested with fake providers only.** The [worker](../gitlab_world/selection_worker_v066.py) accepts one frozen `start_selection_attempt()` result and returns a `cua-full-study-selection-saved-result-v1` object for exactly 20 bound GitLab selection identities, together with its paid attempt IDs and private evidence references. The [source-bound offline receipt](evidence/gitlab-v066-selection-worker-offline-2026-09-28.json) records 19 synthetic tests. No live GitLab selection task, Qwen sample, E2B sandbox, researcher campaign or official final attempt was run. The [100-ID GitLab GUI development requalification](evidence/gitlab-requalification-100-2026-09-28.md) is separate evaluator-controlled evidence and remains unchanged.

Before any cost reservation, the worker requires the actual private six-cell ratification, the exact GitLab runtime/verifier/adapter hashes, a journaled selection start, 20 distinct selection-only IDs and package hashes, and a selected sampler path reopened from the campaign's mode-0600 Tinker checkpoint result. A mismatched path hash or base model is rejected. The evaluator resolves each ID only against the private original GitLab selection partition, starts a fresh overlayfs clone, checks the full baseline and uses the non-admin selection operator. The model receives the current original-GitLab screenshot, visible controls and task instruction through the common Qwen/Qwen3.8-27B v0.6.6 renderer/action contract. It cannot receive evaluator gold or a final-task package.

Each selected task has one durable `storage_application` runtime reservation before opening its local GitLab clone and at least one task-bound `tinker` reservation before model sampling. Both paid work and request fields bind the task ID, package SHA-256 and selected checkpoint SHA-256; additional Tinker reservations correspond to additional screenshot/action turns. GitLab is self-hosted, so no E2B cost is invented. Its local application charge is a frozen-cap-based nominal meter with an unknown external invoice; rendered input and returned output tokens are not treated as a Tinker invoice. Provider usage reconciliation remains a distinct campaign step before selection freeze. The Tinker sampler is constructed inside the first already-reserved callback, checks the selected path's Qwen base model, and samples a real image-plus-text prompt; the implementation follows the pinned local SDK and the official [Tinker sampling client](https://tinker-docs.thinkingmachines.ai/tinker/api-reference/samplingclient/) interface. Context7 returned a monthly quota error during implementation, so no API detail was inferred from its failed lookup.

The worker saves every frame before the corresponding paid call, rechecks its pixels and URL after sampling and immediately before any Playwright GUI action, and rejects navigation outside the assigned selection project. A malformed model action or action/wall-time ending remains a model trace outcome; the binary score comes from independent PostgreSQL and Git saved-state readback after a browser reload. The [selection oracle](../gitlab_world/selection_oracle_v066.py) checks the four original selection workflows and unrelated-state preservation. Its issue-close candidate expects the persisted `state_id` mapping of 1 opened and 2 closed from [GitLab's Issuable source](https://gitlab.com/gitlab-org/gitlab/-/blob/3c9f65d35d68cf2e13e3f1de9965703c7f81c84e/app/models/concerns/issuable.rb); the pinned GitLab 18.5 instance still needs a pre-result live positive/negative control for this workflow. After scoring, the used clone is destroyed and a distinct clone must reproduce the complete frozen baseline. Any uncertain provider, verifier or reset event leaves a private failure trace and cannot emit a scored 20-task result.

The returned mode-0600 `<out_dir>/task-ledger.private.json` has schema `envloop-gitlab-v066-selection-paid-task-ledger-v1`; `run_attempt` returns its absolute path and SHA-256. Its 20 ordered rows bind task ID, package and checkpoint hashes, saved-state/verifier/reset hashes, one application paid ID, a nonempty list of Qwen paid IDs, and the corresponding private task receipt. The batch receipt binds this ledger, all task receipts and the saved-result bytes. The caller must review these artifacts and pass the result and paid IDs to `record_selection_scored`; the worker does not promote a checkpoint itself. The cell-neutral controller's self-hosted paid-category mapping is a separate integration dependency.

The offline tests cover all four selection oracle targets and collateral negatives, 20-row dispatcher schema compatibility, per-task paid coverage, selected checkpoint tampering, frame staleness, model-invalid and wall-time outcomes, exact cold reset, source partition/ACL checks, fake Tinker SDK path/base-model behavior and private evidence tampering. Docker and Colima commands are blocked by test stubs. Remaining work is source-bound live selection calibration, the complete six-cell freeze, provider and local-runtime cost reconciliation, 24 researcher chains and final evaluation. This document reports no model accuracy or improvement.
