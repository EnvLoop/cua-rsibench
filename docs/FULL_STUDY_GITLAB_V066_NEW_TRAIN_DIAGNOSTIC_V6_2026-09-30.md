# GitLab CE v0.6.6: one-use new TRAIN identity GUI diagnostic

The source-frozen v5 boot-only probe completed three exact cold boots in the original GitLab CE evaluator checkout. It did not exercise a browser task and cannot rule out an intermittent startup failure during GUI work. The original final-roster continuation remains terminal after a no-replay infrastructure failure at its fourteenth identity. This v6 source proposes one **new TRAIN-partition** GUI diagnostic, outside all 20 source families in the prospective v4 final replacement cohort. It never replays the terminal final identity and does not count a diagnostic result as a final-task admission.

The private selector takes the third `issue_label_from_alert` TRAIN task after sorting that workflow by task ID. It verifies the 20-task TRAIN inventory and five label candidates, checks that the first two TRAIN identities were the earlier paid attempts, requires a different project and source family, and binds the selected canonical task package. The original frozen baseline has neither the active nor historical target label link. The task ID, prompt, source record, and target label remain in mode-0600 private evidence; the public freeze reports only partition, counts, source hashes, and the nonce commitment. The selector and freeze also bind the independent v5 boot audit, v4 replacement plan, original evaluator checkout scope, and terminal final-task boundary.

Only a later explicitly reviewed `run-diagnostic --execute` may write the single O_EXCL private intent. A 3,600-second process-group watchdog bounds the one child. The evaluator uses a non-admin TRAIN account and a fresh browser context for three UI cases: label the active issue, apply the same plausible label to its historical duplicate, then label the active issue again after reset. Every case saves source-policy and issue screenshots, before/after PostgreSQL and Git snapshots, the independent TRAIN oracle result, a controlled wrong-object check, an exact cold-reset readback, and private raw Docker startup stdout/stderr plus State-only inspect bytes before the next clone or any failure cleanup. The expected scores are 1/0/1. Requests outside the original local GitLab UI are blocked. No model or final/selection task is dispatched.

If a GUI case, reset, saved-log capture, or state readback fails, the child stops and the same intent cannot be replayed. A supervisor fallback saves the current container's logs before attempting an exact cold reset after confirmed child-process-group termination. It does not reset when a live child may still mutate the world. The read-only audit reopens the saved task identity, screenshots, raw bytes, and before/after/restored states; it recomputes the TRAIN oracle and exact wrong-object delta rather than trusting the child's score label. The public outcome, if a run is authorized later, contains only status, scores, counts, and hashes.

The source freeze and its audit do not run a browser, Docker clone, provider request, or task. A passing TRAIN diagnostic would be evidence about this original-software GUI route only. The proposed 100-task final cohort still requires reserve-family bootstrap, a new frozen baseline and ACL proof, full per-task qualification, and the researcher/model runs.
