# Full-study final evaluation dispatch contract (implementation v1)

`src/cursibench/full_study_final_dispatch_v1.py` is the private execution boundary between the [post-campaign matrix](FULL_STUDY_MATRIX.md) and the [result audit](FULL_STUDY_RESULTS_AUDIT.md). It has no built-in application worker or final-task dataset. It cannot turn the existing offline candidate inventories into official scores.

Before constructing a controller, `FinalGate` rebuilds the evaluator-owned six-cell matrix from its source manifest. It requires its byte-identical prepared plan, the previously published immutable pre-campaign witness, the six-cell v0.6.6 ratification, 600 admitted final identities, and all 24 selection-freeze receipts. Each freeze must match its campaign journal's training-checkpoint lineage, selection events, selected checkpoint and timestamp. The private campaign dollar ledger must have a settled Tinker training attempt for every researcher, with no pending, dispatched, uncertain, or overrun attempt. The gate checks the frozen qualified reset baseline for all 600 tasks.

The final retry rule is a constant in the implementation: at most one retry after a recorded `provider`, `transport`, `environment`, or `verifier` infrastructure-invalid attempt, reconciled usage, and a verified cold reset. A model action or wall-time limit is a scored zero, never an infrastructure exclusion. Before the first hidden final dispatch, publish `docs/evidence/full-study-final-dispatch-freeze.json` at an immutable Git commit. Its exact fields must be `schema`, `status`, `study_id`, `pre_campaign_public_witness_sha256`, `matrix_manifest_sha256`, `matrix_plan_sha256`, `completion_index_sha256`, `ratification_sha256`, `retry_rule_sha256`, `selection_freeze_sha256_by_campaign`, and `official_final_model_attempts_before_freeze`. `FinalGate` fetches that file from the commit-specific GitHub raw URL and requires an exact match, including zero prior official final attempts. The completion index is private, `cua-full-study-final-dispatch-gate-v1`, with the study and matrix hashes, retry-rule hash, and exactly 24 `{cell_id, researcher_id, selection_freeze, campaign_journal}` references rooted under ignored `work/`.

Each cell needs a separately reviewed, original-software implementation of `TrustedFinalWorker`. Its frozen identity binds the cell's source snapshot, runtime, action contract, verifier, and ratified adapter source hash. The model-facing capability is only the current screenshot and validated GUI action. The controller command passes an opaque task ID and package hash, checkpoint binding, common v0.6.6 profile, frozen sampling settings, action/wall bounds, and the qualified initial-state hash. It passes no gold, verifier code, package contents, application API credential, or filesystem capability to the actor. The worker must resolve the task package on its evaluator side, start a fresh original-software state, use the common Qwen vision renderer and current-frame action validator, save native application state, independently score no-regression, and cold-reset even after an invalid attempt. The controller rejects worker receipts without those proofs and checks private file bytes on final receipt materialization. Source hashes do not replace independent inspection of the worker and raw GUI/state evidence.

`cua-full-study-final-sampler-bindings-v1` is a private owner list bound to the matrix plan. It has one row per **unique checkpoint**. Shared-base owners use `sampler_path: null`; selected owners require a Tinker sampler URI whose SHA-256 equals the selected checkpoint hash and whose observed base model is `Qwen/Qwen3.8-27B`. A selected slot with the same checkpoint as its base reuses the base owner and never creates a duplicate execution. The controller dispatches the unique owners in frozen cell/slot/task order. Every attempt reserves its frozen per-task plus first-in-chunk cost envelope in the append-only dollar ledger, records its exact command before invoking the worker once, and preserves an ambiguous callback as uncertain without automatic replay. One worker-returned infrastructure-invalid attempt can be retried only after its usage settles. The per-attempt private journal records costs, saved-state/verifier/reset and action/observation hashes, action/turn/wall/provider-latency metrics, timeout subtype, and retry provenance.

After 100 scored tasks for one owner, `materialize_execution` writes a private `cua-full-study-final-execution-v1` receipt and a `cua-full-study-execution-telemetry-v1` receipt. It rechecks every raw artifact and budget settlement and runs the existing result receipt validator. A full run covers six shared-base owners and up to 24 selected owners, producing 3,000 matched **slot-task** outcomes from 600 distinct task identities; the number of unique checkpoint-task executions may be lower when a selected checkpoint is reused. The operator must then build the complete execution and telemetry indexes, reconcile provider invoices and all campaign usage, run the result and publication audits, and obtain six independent cell reviews before any full-result PDF is published.

`tests/test_full_study_final_dispatch_v1.py` uses a synthetic six-cell matrix and fake workers to verify the gate, one 100-task owner with a preserved infrastructure retry, telemetry compatibility, checkpoint reuse, version rejection, and ambiguous-dispatch no-replay. Those booleans are controller tests, **not** authentic application admissions or model outcomes. No real cell worker, paid final evaluation, or official hidden-task result is included in this implementation.
