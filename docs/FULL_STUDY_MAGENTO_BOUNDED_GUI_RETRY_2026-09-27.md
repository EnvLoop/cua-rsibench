# Magento bounded pre-admission GUI infrastructure retry — 2026-09-27

**Pre-result amendment.** During the serial original-Magento evaluator sweep, a candidate's real-admin positive control saved and scored **1**, and its positive app/search pair was cleaned. A fresh negative clone was seeded, but Magento's native CMS grid repeatedly detached or hid the row's “Edit” action. The evaluator's visible click timed out before the quote could be opened and before any negative edit. The sweep stopped; it did **not** map the timeout to a model score. The original process stderr, step hashes, seeded clone and initial-state snapshot were retained. An independent read-only inspection confirmed the live seeded clone still matched its material baseline: target prices, quote, other catalog/business hashes and unrelated search documents were unchanged. The two exact, mount-free container identities were then bound to their preparation receipt and retired under an explicit cleanup receipt. The failed attempt remains in the private journal.

The [one-case recovery gate](../tools/sweep_magento_original_gui_controls_v1.py) permits **one** fresh-clone retry of that specific stopped candidate only when the prior journal ends in the matching operator reconciliation, the saved positive remains 1, the failed negative control never reached its GUI mutation, material state was unchanged, both exact containers were cleaned, and no recovery from the same journal has already been dispatched. The retry must use the unchanged candidate plan, pinned Magento application/search images, original GUI controller and independent saved-state verifier. It reruns the complete positive, fresh reset and wrong-variant negative on two newly created app/search pairs; no partial earlier success is promoted into the new control. A second infrastructure failure leaves the candidate unqualified and requires a new pre-result source/cell decision. This rule does not retry a scored wrong-object negative, a saved-state false positive, or a model outcome.

The [field-limited failure receipt](evidence/magento-original-negative-neutral-interruption-2026-09-27.md) records one stopped evaluator attempt and one identity-bound cleanup. It contains no task ID, quote, price, account secret or hidden model trace. Magento's first 25 distinct passing GUI controls remain unchanged. **Official Magento final admissions and full-study model calls remain zero.**

The subsequent [one-time recovery audit](evidence/magento-original-negative-neutral-retry-2026-09-27.md) confirms a fresh full-task positive 1, wrong-variant 0, material reset, two cleaned pairs and exactly one dispatched retry. The original timeout is still counted as an evaluator failure. The [30-case aggregate](evidence/magento-original-gui-progress-30-2026-09-27.md) includes the recovered candidate as one distinct development GUI control, never as a model score or official admission.
