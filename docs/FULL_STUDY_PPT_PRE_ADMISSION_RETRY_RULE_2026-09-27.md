# PowerPoint evaluator pre-admission retry rule — 2026-09-27

**Pre-result rule.** A PowerPoint final candidate cannot enter the study until an evaluator-controlled GUI positive, partial negative, collateral negative, fresh-copy reset, application-native baseline and independent downloaded-PPTX readback all pass. These checks are task qualification, never hidden-model scores. No Qwen or researcher has encountered the candidate pool yet.

A bounded **one-time fresh-copy retry** is permitted only when an evaluator GUI/control action fails for an infrastructure reason before the complete per-ID admission receipt exists. Examples are delayed Office editor readiness, an inaccessible thumbnail shadow root, or a stale OneDrive download. The failed attempt's cloud file, downloaded bytes, controller exception, source/plan/controller/verifier hashes and exact completed phase are retained privately. The evaluator must create a new file from the unchanged original task source and use the **same frozen controller and verifier bytes**. The original attempt is never silently continued, overwritten, deleted, or converted into a pass. A retry may not use information about a hidden model outcome, since no model is dispatched before admission.

This rule does **not** retry a completed saved-state score of 0 caused by changed chart, workbook, source facts, non-target content or an incorrect positive. Such a candidate stays failed; any source/task revision is a new pre-result amendment and the affected source family is excluded from the current final pool. If the fresh-copy infrastructure retry also fails, the candidate is ineligible for the current pool and its source family is replaced before the six-cell freeze. The public aggregate will count original failures, retried successes, unresolved candidates and the number of replacements separately.
