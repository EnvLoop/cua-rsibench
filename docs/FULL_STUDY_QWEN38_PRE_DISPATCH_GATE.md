# Read-only Qwen runtime gate before paid campaign work

The [pre-dispatch interface](../src/cursibench/full_study_qwen_runtime_gate_v1.py) is an audit function for a future `FrozenStudy`/`CampaignSession` call site. It reopens the public clean-runtime/toy receipt, frozen runtime specification, wheel lock, original toy runner and read-only attester source hashes, and all four private toy files. It checks the private checkpoint binding and provider-reported base model without exposing the checkpoint URI. It then launches the dedicated root-checkout venv's [offline verifier](../tools/verify_qwen38_training_runtime_v1.py) as a subprocess with provider credentials removed and Hugging Face offline mode forced.

The function takes the root checkout path, the frozen study-plan SHA-256, and the private second-toy evidence directory. It requires the venv at `work/qwen38-training-runtime/.venv`, the pinned cookbook checkout at `work/tinker-cookbook-pinned`, and the private toy directory under `work/full-study/` **in that same durable root checkout**. The current preparation venv and private toy files are in separate ignored worktrees, so this gate will fail until the runtime is rebuilt in the root checkout and the private evidence is securely relocated with bytes and mode 0600 preserved. The [runtime build procedure](FULL_STUDY_QWEN38_TRAINING_RUNTIME.md) documents that step.

A successful return binds the study plan, runtime-spec hash and public toy receipt hash, reports zero provider calls, and explicitly sets `dispatch_authorized` to `false`. It does not modify the campaign journal, reserve dollars, train, sample, open a GUI, or grant permission to use selection/final tasks. The parent controller must call this immediately before its first paid Qwen operation and ensure that the actual worker process uses the same verified dedicated interpreter. The existing six-cell freeze, source/task partition, budget and replay gates remain separate. Three fake-only tests cover the positive read-only audit, private-file mode drift, and a verifier failure. No campaign controller or frozen action/adapter source was changed here.
