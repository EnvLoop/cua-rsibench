# PowerPoint Web teacher episode worker

**Status: prospective train-only implementation; no live Office, Graph, E2B, teacher, or Tinker call has used this worker.** The six-cell v0.6.6 ratification and authentic pre-campaign manifest are not present. Offline fake-provider tests do not admit a benchmark task or start a researcher campaign.

`tools/office_web_ppt_teacher_worker_v1.py` implements the PowerPoint-for-the-web `cell_worker.run_episode(task, out_dir, sample_teacher, dispatch_e2b)` contract consumed by `collect_train_batch`. The worker receives only one frozen **train** task identity, package hash, and visible instruction. It rejects selection/final paths and checks a private normalized PPTX, the original WDI task specification, exact frozen runtime/verifier hashes, its own source hash, and the six-cell common action-profile ratification before any E2B or Graph reservation.

The actor receives one assigned PowerPoint file, edited through the original Office web GUI inside a bounded E2B Desktop 2.2.0 lease. The pre-existing manual-login bridge starts a secure, password-protected desktop. Before the teacher sees a screenshot, an operator must sign in as the distinct actor account and place a fresh one-file ACL receipt: the assigned item has exactly one specific-person write grant; its parent is unshared; an unrelated sentinel is denied; and the assigned file is visibly editable. `office_web_e2b_train_runner_v1.admit` independently verifies that receipt against the exact sandbox, task, edit URL, lease, and train split. A missing or changed receipt kills the actor sandbox and stops the episode.

Every model action is tied to the current screenshot and v0.6.6 observation; the E2B desktop dispatcher rechecks pixels immediately before a native mouse/keyboard action. Frames and teacher responses stay in private mode-0600 files. The actor lease must terminate after `finish`. An evaluator with a separate delegated OneDrive owner identity then performs **two** exact-item downloads through Microsoft Graph, requiring stable item ID, drive ID, name, size, eTag, and byte-identical PPTX contents. The original WDI OOXML verifier independently scores the saved file against the frozen Office-normalized baseline. A partial target change, native-chart rewrite, or unrelated slide change fails the episode.

Before the reset copy is shared, the owner removes the actor's prior grant and Graph confirms its permissions list is empty. A **new** E2B desktop opens a distinct, owner-prepared neutral PowerPoint copy. Its own fresh one-file ACL receipt is required. The worker double-downloads that copy, requires zero target changes and no unrelated changes under the same verifier, terminates the reset sandbox, and confirms that copy's actor grant was also removed. Only then does it write the exact saved-state, reset, frame, action-trace, and episode receipts accepted by the shared teacher adapter. E2B leases, owner readbacks, and permission checks use the campaign's paid-dispatch ledger; an ambiguous call is retained for reconciliation and never silently retried.

The owner readback module uses [Microsoft Graph v1.0 driveItem metadata](https://learn.microsoft.com/en-us/graph/api/driveitem-get?view=graph-rest-1.0), [file content](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content?view=graph-rest-1.0), and [permission listing](https://learn.microsoft.com/en-us/graph/api/driveitem-list-permissions?view=graph-rest-1.0). A delegated owner `Files.Read` token is read from `MS_GRAPH_OWNER_TOKEN` on the host only; it is never given to the actor, put into a model request, or committed. Graph's preauthenticated content redirect is fetched **without** the bearer token. Item IDs, edit URLs, account identities, task gold, PPTX files, and permission screenshots stay under ignored private `work/`.

This path still requires a real owner token, a manually authenticated actor for each new desktop lease, prepared distinct train/reset cloud items, verified ACL snapshots, frozen task binding, and provider billing reconciliation. It does not solve high-volume unattended Microsoft login or prove a 24-campaign result. The current Mac UI lock prevents a live Office pilot, so the only evidence is 15 offline tests covering exact double downloads, owner/drive/permission mismatch, source or ratification drift, missing ACL cleanup, current-frame change, saved-state partial failure, reset drift, and the shared teacher-adapter receipt contract. Context7's monthly quota prevented its E2B documentation lookup; the implementation was checked against the repository-pinned E2B Desktop 2.2.0 source and existing train-only bridge.

For an admitted campaign, `prepare_private_binding(session, task=..., task_path=..., normalized_baseline_path=..., actor_item=..., reset_item=..., owner_email=..., actor_email=..., out_path=...)` writes a new mode-0600 binding and rechecks the WDI baseline without a provider call. Construct `OfficePptTeacherWorker(session, binding_path)` and pass it to `collect_train_batch(session, round_index, train_context_path, out_dir, worker)`. That collector returns the private dataset manifest and in-memory v0.6.6 Qwen datums for the separately budgeted Tinker SFT step. The actor and reset E2B sessions each require operator-created `run.private.json` and `actor-scope.private.json` after manual sign-in; both grants must be revoked and independently re-read through Graph before the episode is admitted. No evaluator task gold or owner Graph token enters the teacher prompt.
