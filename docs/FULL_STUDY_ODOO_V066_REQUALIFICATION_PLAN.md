# Odoo Community v0.6.6 GUI requalification plan

**Status, 2026-09-28: source-bound offline plan only.** The [public aggregate](evidence/odoo-v066-prospective-gui-requalification-2026-09-28.json) binds one evaluator-private 140-identity plan to the new six-cell action-source ratification (`49f6a047…`). The plan contains 20 train, 20 selection and 100 hidden-candidate package identities, each paired with its original checkpoint, baseline snapshot, source-asset hash, visible-instruction hash, family and current Odoo action adapter. It reopens the [post-hardening 140-ID historical audit](evidence/odoo-private-evidence-hardening-2026-09-28.md) before building. No new v0.6.6 per-ID GUI attempt, model call, campaign or official final task is present. The hidden IDs and task instructions remain in mode-0600 evaluator-private storage.

The first live gate is **one train-only task** selected in the private plan. It must wait until the competing self-hosted control lane is idle. A new exclusive Odoo worker lease and a new private attempt directory are required; failed or uncertain attempts remain intact and are never replayed automatically. The future controller must cold-restore PostgreSQL and the physical filestore, prove an unsolved independent baseline, display the task source in original Odoo, then use only fresh screenshots and the v0.6.6 current-frame GUI dispatcher for a known-answer positive and a distinct wrong-object negative. It must reload the browser before each evaluator readback. The SELECT-only evaluator saves complete SQL snapshots, physical filestore manifests and attachment store paths after each phase. A final cold restore saves the restored SQL snapshot and filestore manifest. Raw frames, action contract receipts and lease events stay private. An independent reviewer must inspect the saved source frame after the attempt and bind their review to its hash and the source-asset hash.

The [pilot auditor](../enterprise_fallback/odoo18/v066_requalification_pilot.py) accepts only the frozen public/private plan pair and a new mode-0600 attempt receipt inside the train worker's private tree. It reopens every referenced artifact and current source/checkpoint binding. Its reward is **derived from the saved SQL state and private gold using the pure verifier functions**, with protected source-file and attachment-path comparisons added separately. It requires baseline reward 0, positive reward 1 with no regression codes, and negative reward 0 with exactly the family-specific wrong-object code. It also checks the full post-reset SQL and filestore against the frozen baseline, the exclusive lease interval, the PNG viewport, ordered GUI action/frame bindings and the independent visual review record. A bare `passed: true` field cannot substitute for any of these inputs. The auditor makes no Docker, browser or provider call and writes no score unless a real receipt is supplied.

The plan and pilot gate are deliberately narrower than the complete requalification lane. The live recorder and independent visual review still have to be executed on the original application. After a real train pilot passes and its raw artifacts are reviewed, the same frozen protocol must be extended to all 20 train, 20 selection and 100 hidden candidates under separate private runs, without exposing hidden values to researchers. Current actor ACL/SELECT-only privileges, application access, model-action timing, budget and the full six-cell pre-campaign witness require separate fresh evidence before official admission. **Fresh current-profile GUI controls: 0/140. Official Odoo final tasks: 0/100.**
