# Full-study researcher campaign dispatcher

**Status: implementation candidate, zero official campaigns.** The repository has no authentic six-cell pre-campaign manifest, no ratified common v0.6.6 action profile, and no immutable public freeze witness. The dispatcher refuses paid work in that state. The 600 offline candidates and evaluator development controls elsewhere in this repository are not 600 official admissions.

The controller in `src/cursibench/full_study_campaign_dispatch_v1.py` is designed for the preregistered four-researcher by six-cell matrix. It rebuilds all 600 per-task qualifications from the source manifest, byte-compares the prepared 24-intent plan, validates the common action-profile ratification, and fetches a witness from an immutable `EnvLoop/cua-rsibench` GitHub commit. The witness must bind the pre-campaign manifest hash, plan hash, ratification hash, and each of the six action-contract hashes. Neither the witness nor the ratification is generated by this code. Publishing an unchecked local JSON file does not satisfy the gate.

Each opened campaign receives a private mode-0600 hash-chained journal and uses the existing global full-study dollar ledger. The 16-hour clock starts once per campaign. A paid request reserves its category dollars and applicable call/token/candidate/sandbox counters, writes the exact request privately, records its hash, and marks dispatch **before** calling a provider. A completed provider response remains separately billable until an account usage receipt settles it; an uncertain response retains its reservation. A crash before journal registration leaves an orphan budget attempt that must be reconciled, and a crash after dispatch never triggers an automatic replay. Provider overrun stops new paid work. Existing journals remain readable after the 16-hour limit for accounting.

The researcher path uses the frozen system-prompt and AgentRouterHub rate/route assets with OpenAI Responses. It sends only evaluator-approved training instructions and the 20 selection-task feedback; it validates the proposal's task IDs against frozen **train** identities. The Qwen training path accepts only a rendered v0.6.6 train batch whose source task/package hashes match that proposal and the frozen train split. It starts a fresh `Qwen/Qwen3.8-27B` LoRA lineage, executes the frozen optimizer schedule, saves sampler weights, checks the sampler's base model, and samples a train-only prompt. Its actual checkpoint path remains private. The local quote is a conservative published-rate envelope, not a provider invoice; the external usage receipt is mandatory before selection freeze.

The selection state machine exposes only the 20 frozen selection identities to a cell-owned native-GUI worker. Every full 20-task attempt gets a durable start record; an infrastructure-invalid attempt stays visible, and a second attempt requires a frozen retry-rule hash. A scored result requires saved-state, independent verifier, and reset receipt hashes for every task, plus traced Tinker sampling and the [six-cell environment-cost class](../src/cursibench/full_study_selection_environment_v1.py). The [paid-task coverage audit](../src/cursibench/full_study_selection_paid_coverage_v1.py) reopens every hash-bound paid request, requires a distinct task/package/checkpoint-bound Tinker sample for all 20 identities, and requires either task-bound environment leases or one exact 20-task environment lease. It refuses omitted, uncertain, or pre-start paid calls and rechecks its private receipt when feedback is reused. PowerPoint-web, Excel-web and native Desktop require actual E2B reservations; self-hosted Odoo Community, GitLab CE and Magento require `storage_application` reservations and cannot claim E2B as their environment. A local planning reservation or measured host runtime is not a provider invoice. Promotion requires more selection wins **and zero regressed selection tasks** relative to the incumbent. The selected checkpoint and lineage are frozen before any final evaluation. The dispatcher has no method to return final task instructions or to score hidden final tasks.

The original-software teacher-episode collectors, v0.6.6 multimodal episode renderer, and six cell-specific 20-task selection workers are **not yet integrated**. They must provide independently verified train/selection artifacts and call the same paid ledger. Current `gui_sft_episode_v2` still renders the older output contract and cannot be silently used as a v0.6.6 study batch. The code does not transform arbitrary model text or a synthetic verifier receipt into official evidence. The six-cell public freeze, real provider balances/rates, actual billing reconciliation, 24 completed training chains, and 3,000 final slot-task results remain outstanding.

The CLI at `tools/full_study_campaign_dispatch_v1.py` supports gate inspection, campaign start/status, evaluator-owned base selection import, a real AgentRouterHub researcher call, selection attempt start/invalid/scored registration, usage reconciliation, and checkpoint freeze. `dispatch_tinker_sft` is a Python API because its datums are in-memory multimodal objects produced by a trusted renderer. The CLI prints hashes and counts only; it does not print private task views or checkpoint paths.

Validation currently consists of synthetic six-cell, fake-provider tests for rejection of missing or changed freezes, no hidden final task in researcher input, source-disjoint training, one-time paid dispatch, crash/orphan reconciliation, 20-task selection coverage, infrastructure retry, strict no-regression promotion, and freeze. Those tests exercise code behavior, not real campaign execution.

Tinker API compatibility was checked against the pinned local SDK and the official [Tinker ServiceClient](https://tinker-docs.thinkingmachines.ai/tinker/api-reference/serviceclient/) and [TrainingClient](https://github.com/thinking-machines-lab/tinker/blob/main/src/tinker/lib/public_interfaces/training_client.py) references. Vision rendering follows the official [Qwen3.8 renderer](https://github.com/thinking-machines-lab/tinker-cookbook/blob/main/tinker_cookbook/renderers/qwen3_8.py) and the repository's prior train-only compatibility smoke. Context7 CLI documentation lookup reached its monthly quota during this work; no API detail was inferred from an unsuccessful Context7 response.
