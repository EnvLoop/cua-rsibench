# Read-only native GitLab attribute proof

V2 produced one actual healthy fresh clone with seven critical services running and six optional exporters absent. It ended at the `show-config` filter before a complete cycle was accepted. The exact concealed parser input cannot be recovered after owned teardown; the narrower JSON/parser cause remains unknown. The original instance was restored with identical identity, SQL baseline and Git trees. All 398 native evidence bindings rehash exactly. Neither that healthy boot nor the failed attempt qualifies the three-cycle trial or promotes a task/model outcome.

Installed-source inspection established a separate concrete API problem: `show-config` calls `Gitlab.generate_config`, which can generate and write secrets. The Docker recipe loads `/assets/gitlab.rb`, which evaluates the existing environment and then the mounted configuration. We did not execute it on the protected original. Its use as a read-only effective-config observer is therefore unsuitable even if its parser were repaired.

A plain read of the existing poststartup node JSON confirmed the native schema. All nine fixed boolean paths reside under `default`, with explicit original settings under `normal`; no inferred path or absent-field false value was used. The installed configuration recipe calls `node.consume_attributes(generated_config)` and states that these are the final recipe values. The observed original node-file SHA is `3ebbdd54b4e9d3372cbd215823abb89635fca05e67717dab784305784e9e0f6c`; the fixed typed projection SHA is `19a47772b536c127700178da61894eff3a6176a3e3be78b0772f656696c2c24b`. This observation establishes schema and provenance, not qualification of the proposed disabled profile.

V3 reads the fresh clone's fixed `/opt/gitlab/embedded/nodes/gitlab-neutral.local.json` with ordinary Ruby file reads. It does not invoke Cinc, `show-config`, secret generation, configuration evaluation, or reconfiguration. The full JSON stays inside the container. Only file hash/size/mtime, exact hostname, fixed schema paths, typed booleans, and a fixed parse-error class can leave it. String values and credentials are never emitted.

The artifact must be a regular nonsymlink file, match the owned clone hostname, and have an mtime at or after that container's exact UTC start timestamp. Each of the nine explicit profile declarations must survive as a typed false value under native `normal` attributes. The fixed `override`, `normal`, and `default` layers are inspected; the effective value follows that precedence and must remain false. Defaults alone cannot qualify an ignored declaration. Missing fields, unexpected types, stale artifacts, changed names/paths, or overriding true values fail with retained diagnostics. The six exporter service states and seven critical service states remain independently checked.

The SQL/Git state snapshot is now written immediately after readiness, before Git-tree extraction and attribute reading. A later reader failure therefore leaves a durable baseline snapshot rather than only a partial in-memory readback. Complete Git trees, startup/state logs, config-delta proof, native manifest, teardown, original restoration, and independent saved replay retain their existing requirements.

V3 is an additive namespace and pins unmodified V1 and V2 code. The same image, operators, immutable lower seeds, business baseline, source cores, telemetry suffix, COW ownership, host 8026/internal 8018 mapping, SVWAIT 60, readiness 900, no-retry lifecycle and separate supervision directory remain in force. Source preparation alone authorizes no new boot. The fresh plan needs independent exact review; zero task/model/control credit remains the neutral-trial boundary.

Use `python -m gitlab_world.v066_neutral_telemetry_coldboot_v3` with the existing `prepare`, `review`, `run`, and `audit` arguments. Supervision scripts, streams and terminal receipts must use a separate private sibling from launch. The source-only tests execute the reader against real local fixture bytes, reject default-only credit and stale/overridden/nonboolean artifacts, prove the real boot path saves its snapshot before a forced later reader failure, and replay saved attribute receipts. They do not demonstrate a successful three-clone native trial.
