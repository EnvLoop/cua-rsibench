# One shared-base selection per cell before researcher campaigns

**Status: source-bound execution path and admission gate, verified with fake providers only.** The initial `record_base_selection` interface accepted a bare 20-score object. A forged result with plausible hashes could have become the common baseline for four researchers without proving an original-software run or accounting for its cost. The [shared-base validator](../src/cursibench/full_study_shared_base_selection_v1.py) now requires one private, source-bound `cua-full-study-shared-base-selection-receipt-v1` per cell before a campaign can open. The [execution controller](../src/cursibench/full_study_shared_base_execution_v1.py) reuses the existing GitLab CE and Odoo Community v0.6.6 selection workers under a dedicated `cell:shared-base` owner. The [offline aggregate receipt](evidence/shared-base-execution-offline-2026-09-28.json) records the fake-provider checks and source hashes. No actual shared-base task, paid model call, researcher campaign, or hidden-final task has run.

The frozen plan reserves the cell's **full 100-task base-final cost maximum again** as a conservative, separate upper bound for its 20-task base selection. That includes possible startup and fixed charges without assuming they scale linearly with task count. The six selection bounds and six base-final bounds enter the global all-in ceiling once each; 24 researcher campaign caps remain separate. The `cell:shared-base` dollar owner can reserve Tinker and only the cell's actual E2B or self-hosted `storage_application` category. The controller additionally caps their combined committed selection amounts at the separate selection bound before each dispatch. A reservation is nominal budget protection, not a provider invoice.

The receipt path is fixed at `work/shared-base-selection/<cell>/receipt.private.json` and must be mode 0600 under a private directory. It binds the immutable study plan, base manifest/checkpoint freeze receipt, exact `Qwen/Qwen3.8-27B` base-model name, selection identity hash, runtime/action/verifier/adapter source hashes, controller source hash, native worker batch/ledger evidence, standard 20-row saved-result file, task ledger, and actual environment cost class. The base checkpoint SHA is the frozen cell-manifest binding; it is not misrepresented as a hash of provider weights or of the model-name string. The GitLab sampler separately verifies that the Tinker base client reports the exact model name; the Odoo worker uses its explicit base-model path and verifies its sampler identity. For every selection ID, the ledger links current-frame screenshots and per-turn model/action receipts, actor-saved state, an independent target/no-regression verifier that names the exact saved-artifact hash it evaluated, and a cold reset whose baseline and restored bytes match. The validator reopens and hashes each private file and checks the native saved/reset source hashes; no score field alone can satisfy it.

Every task must have a settled, task-bound Tinker sampling attempt whose private paid-result body says `completed`. The environment may use one task-bound lease per ID or one lease whose paid request contains the **exact ordered 20-task roster**. A charged Tinker sampler setup is permitted but gives no task credit. The common [paid-coverage validator](../src/cursibench/full_study_selection_paid_coverage_v1.py) checks this shape, while the shared-base gate additionally reopens each raw worker request/result, normalized paid request/result and usage file against the append-only dollar ledger. Paid work is reserved and dispatched durably before its callback; an uncertain callback is not replayed. An injected trusted usage reconciler must supply the account charge for Tinker or a local opportunity-cost meter for the self-hosted application. Provider invoice amounts and self-hosted nominal metering remain distinct; an unknown or unreconciled charge cannot admit feedback. All related paid attempts must appear, including setup. An omitted or uncertain attempt blocks admission rather than becoming a zero task score.

Before the shared-base controller writes a Tinker request, reserves dollars or invokes its sampler callback, it runs the same [root-owned Qwen runtime gate](FULL_STUDY_QWEN38_PRE_DISPATCH_GATE.md) used for researcher campaigns. The paid request binds the runtime-spec, public toy receipt and gate-source hashes; the admission validator rejects a Tinker envelope without that binding. A failed runtime check creates no request artifact or budget attempt. The synthetic test fixture supplies explicitly fake hashes to exercise receipt structure; it is not a live runtime attestation.

After one receipt is admitted, a mode-0600 registry freezes its SHA-256. Each of the four campaign journals imports the same bytes and records the same receipt hash. Reopening a campaign or preparing feedback rechecks the source receipt, task evidence and paid ledger; replacement or tampering fails closed. The CLI has a separate `base-admit` step before `start`, followed by `base-selection --receipt` for each researcher. Naked JSON score imports are no longer an interface.

The tests create synthetic private artifacts and fake settled paid attempts, run the original GitLab worker with a fake GUI/backend through the new controller, and project an Odoo-native 20-task batch fixture. They cover GitLab-style per-task runtime leases, Odoo-style one ordered-20 self-hosted lease plus sampler setup, four-campaign import of one identical receipt SHA, source tampering, wrong environment class and an extra unaccounted paid attempt. They make no provider, Docker, E2B, or hidden-final call. **Remaining live dependencies:** admit the six real original-software cell manifests and ratification; source-bind their base checkpoint freeze receipts; obtain trusted account/local-usage reconciliation; run each cell's 20-task base selection. The generic PowerPoint, Excel, Desktop and Magento shared-base runners still need corresponding native adapters. These conditions have not been satisfied, so the paper cannot report a measured base score or campaign result.
