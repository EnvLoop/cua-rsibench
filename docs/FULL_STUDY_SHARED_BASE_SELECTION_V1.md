# One shared-base selection per cell before researcher campaigns

**Status: pre-result admission and budget gate, not an executed baseline.** The initial `record_base_selection` interface accepted a bare 20-score object. A forged result with plausible hashes could have become the common baseline for four researchers without proving an original-software run or accounting for its cost. The [shared-base validator](../src/cursibench/full_study_shared_base_selection_v1.py) now requires one private, source-bound `cua-full-study-shared-base-selection-receipt-v1` per cell before a campaign can open. The [source-bound offline receipt](evidence/shared-base-selection-gate-offline-2026-09-28.json) records 44 passing synthetic tests. The six actual selection receipts do not exist, so this change produces no base score, model result, or campaign.

The frozen plan reserves the cell's **full 100-task base-final cost maximum again** as a conservative, separate upper bound for its 20-task base selection. That includes possible startup and fixed charges without assuming they scale linearly with task count. The six selection bounds and six base-final bounds enter the global all-in ceiling once each; 24 researcher campaign caps remain separate. The `cell:shared-base` dollar owner can reserve Tinker and only the cell's actual E2B or self-hosted `storage_application` category. Both draw from the one selection all-in cap, so the same baseline is not charged four times. A reservation is nominal budget protection, not a provider invoice.

The receipt path is fixed at `work/shared-base-selection/<cell>/receipt.private.json` and must be mode 0600 under a private directory. It binds the immutable study plan, base manifest/checkpoint, selection identity hash, runtime/action/verifier/adapter source hashes, standard 20-row saved-result file, task ledger, and the real environment cost class. For every selection ID, the ledger links current-frame screenshots and per-turn model/action receipts, actor-saved state, an independent target/no-regression verifier that names the exact saved-artifact hash it evaluated, and a cold reset whose baseline and restored bytes match. The validator reopens and hashes each private file; no score field alone can satisfy it.

Every task must have a settled, task-bound Tinker sampling attempt whose private paid-result body says `completed`. The environment may use one task-bound lease per ID or one lease whose paid request contains the **exact ordered 20-task roster**. A charged Tinker sampler setup is permitted but gives no task credit. The common [paid-coverage validator](../src/cursibench/full_study_selection_paid_coverage_v1.py) checks this shape, while the shared-base gate additionally reopens each paid result and compares its request and usage files with the append-only dollar ledger. Provider invoice amounts and self-hosted nominal metering remain distinct; an unknown or unreconciled charge cannot admit feedback. All related paid attempts must appear, including setup. An omitted or uncertain attempt blocks admission rather than becoming a zero task score.

After one receipt is admitted, a mode-0600 registry freezes its SHA-256. Each of the four campaign journals imports the same bytes and records the same receipt hash. Reopening a campaign or preparing feedback rechecks the source receipt, task evidence and paid ledger; replacement or tampering fails closed. The CLI has a separate `base-admit` step before `start`, followed by `base-selection --receipt` for each researcher. Naked JSON score imports are no longer an interface.

The tests create synthetic private artifacts and fake settled paid attempts to exercise the positive path, GitLab-style per-task runtime leases, Odoo-style one ordered-20 self-hosted lease plus sampler setup, four-campaign receipt reuse, source tampering, wrong environment class and an extra unaccounted paid attempt. They make no provider, Docker, E2B, or hidden-final call. **Remaining execution work:** a shared-base controller must run each cell's existing selection worker on the frozen base checkpoint under `cell:shared-base`, write this receipt and reconcile actual Tinker/environment usage. The current GitLab and Odoo selected workers are potential reusable engines, but neither has produced a shared-base run. The six-cell ratification and all official final admissions remain missing.
