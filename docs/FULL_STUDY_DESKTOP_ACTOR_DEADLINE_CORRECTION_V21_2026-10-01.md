# Additive actor deadline correction design

The retained TRAIN pilot submitted 25 model samples, completed 24 responses and applied 24 clicks. Its final request entered sampling with approximately 3.5715 actor seconds remaining. The legacy transport floored the wait to three seconds and retained `provider_timeout_uncertain` after approximately 3.0011 seconds. This was an actor-budget-constrained timeout; the old records do not prove literal exhaustion of all 720 seconds. The source-frozen invalid pilot, its paid intents and invoices remain unchanged. No task score is inferred from these records.

The ledger has 27 consumed paid intents and dispatch records: one sampler setup, one actor environment and 25 samples. It has 26 successful paid result files because the final sample's uncertain result is retained in the sampler RPC and durable vision journal. Actor guest cleanup returned successfully and its status check reported stopped. The sampler child was terminated without a retained service-close acknowledgement, so provider session cleanup remains unverified. Dollar cost and billed tokens are unknown.

This design adds a v21 namespace with the same 90 actions, 720 actor seconds, 1,200-second environment lease, two environment creates, output-token bound and source-reviewed model policy. It applies identically to all five model slots. It does not modify or reinterpret the original v11 pilot files. The primitive and runtime wiring are now implemented in a separate source namespace; native dispatch remains disabled pending a fresh root review and permit. The concrete entrypoint is documented in `FULL_STUDY_DESKTOP_DEADLINE_RUNTIME_V21_2026-10-01.md`.

1. Pass the absolute actor monotonic deadline into the source-bound clean sampler RPC. The parent and clean child use the same host monotonic clock. Recompute remaining time before actual model submission and future waiting. Stop only at an actual deadline event, without a predefined minimum remaining cutoff or integer truncation. The pinned SDK accepts a floating-point timeout. Keep the provider's existing 120-second cap. If the existing limits object requires integer fields, its ceiling can hold the upper bound while `DeadlineFuture` passes the exact lesser float to the already-submitted future.

2. Wrap each submitted future exactly once. A timeout at or after the actual actor deadline yields an explicit actor deadline proof. An earlier independent provider timeout keeps its existing provider fault classification. A result completed after the deadline remains privately retained and is never returned for GUI application. The primitive contains no provider submission, retry, cancellation, browser control or score assignment.

3. Retain the original vision journal result and attach a separate hash-bound actor deadline proof to the new RPC result. The existing vision adapter catches timeout subclasses; the new clean sampler must retain the wrapper's proof explicitly instead of losing it inside a generic `provider_timeout_uncertain`. A consumed request stays poisoned. Split validated RPC acknowledgement from uncertain model completion in cleanup metadata. Permit only bounded shutdown acknowledgement after poison, without reopening setup, gate or sample commands. Record provider service close completion and an owned session identity hash when available; otherwise retain cleanup uncertainty.

4. Add a typed actor-budget branch inside the uniform episode, before model normalization or GUI dispatch. Record the consumed sample and a not-applied trace entry, then stop the actor loop. Do not classify every provider timeout as budget exhaustion. Do not infer zero, fabricate a model finish action, apply a late result or resubmit the failed request. The legacy pilot ended with approximately 0.57 seconds left after its integer-clipped wait, so it retains its original invalid status and a separate retrospective origin diagnosis.

5. Continue the existing trusted saved-artifact readback and independent verifier only while the episode still owns the guest, no late GUI operation is pending and the model command is poisoned. Perform the existing actor cleanup and distinct fresh reset, require original-byte restoration, then terminate the reset guest. Every artifact and cleanup receipt must pass the same uniform protocol checks. A task score is assigned only after those independent artifacts exist. Any unsafe guest state, failed readback/reset, unresolved native action or cleanup failure remains invalid. Evaluation and reset run outside the actor's stopped 720-second clock without extending either environment lease.

6. Freeze the new sampler, RPC, episode wrapper and source hashes in a new v21 permit and fresh output namespace. The earlier pilot's intent IDs, source freeze and results are never reused. Before native use, add integration tests for acknowledged actor deadline events, earlier independent provider timeouts, late returned samples, poisoned shutdown, trusted saved/readback/reset completion and failures, and identical policy across all five slots.

The nine primitive tests verify exact fractional and subsecond waits, actual deadline proofs, independent provider timeouts, late-result retention, consumed future refusal, legacy attribution without score invention, uniform slot policy and invalid clock inputs. Additional runtime tests exercise the actual RPC, clean adapter and common independently saved/scored/reset episode, including its failures and all five slots. All providers and guests are synthetic; no new native or provider operation was performed.
