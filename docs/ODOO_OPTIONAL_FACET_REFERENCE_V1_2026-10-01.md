# Odoo optional native facet reference epoch

This is a reference-only source amendment. The frozen v12 native adapter, account witness, actor clock, model loop, saved-state scorer, worker lease and exact reset sources are unchanged. No current native acceptance is claimed by these source tests.

The retained v12 selection failed at inventory ordinal 6 after six completed controls. The reference selected a visible facet before `ActionJournal.act`. That method then performed the native readiness/observation; the UI rerender removed the facet before `Locator.bounding_box`, which auto-waited until timeout. There was no button IO for that failed turn. The original namespace, actions, frame and reset remain unchanged; the failed episode is not replayed or reclassified.

`native_reference_facet_v1.recorder_module` loads the exact frozen recorder in a separate declared namespace, retaining v12's truthful rejection stop and all core guards. For an explicit reference-only `optional_facet=True` call it first obtains the journal's actual observation. It then queries the current first native facet with `Locator.element_handles`, and obtains its current `ElementHandle.bounding_box` without locator auto-wait. No candidate, coordinate or stale locator is selected before observation.

If the current element is absent, hidden or detached before intent, the reference chooses an ordinary normalized `wait` of 100 ms. That wait receives its own durable assistant bytes, intent, native guard decision, actual wait driver call, receipt, trace, and consumed step/nonce. The next observation receives a fresh nonce and a new frame filename. No applied click is invented, no action is retried, and no point is redirected to another control. A duplicate handle is fatal before intent. All current native facets are cleared through this ordinary journal path, under the same 90-turn and absolute 720-second budgets.

The policy is task-independent and applies to all four reference families. It has no gold/split/answer branch and no direct task DOM mutation. Model behavior remains the original v12 policy: models receive the native screenshot and must decide which filters to clear through ordinary GUI actions.

`candidate_module` loads a fresh evaluator namespace with the same pinned v12 adapter/reset/scorer. It selects recipes v3 and the supplemental recorder without modifying any existing v12 module globals or files. The additional reference binding includes the native v12 binding and all three supplemental source hashes. `odoo_v066_native_reference_qualification_v1` wraps the unchanged full TRAIN/20/100 qualifier, requires that explicit binding, and writes a fresh reference dispatch intent before any native work. A second call with the same plan refuses; no automatic resume or replay is added.
