# Proposed pre-result action-output amendment — 2026-09-27

The six-cell study has **zero official final model outcomes**. Its historical v0.6.4 minimal-action adapter accepts one whole-response JSON fence and otherwise requires `type`, an allowed GUI action, a current screenshot/control target, and the frozen frame/task binding. A preserved [Odoo training sample](evidence/odoo-fenced-train-sample-offline-replay-2026-09-25.md) motivated the earlier fence-only transport rule; its historical rejection and zero dispatched actions remain unchanged.

Native Desktop training then exposed two different model-output problems under the shared v0.6.4 adapter. Some Qwen3.8 replies used a top-level `action` string where `type` was required. Others copied the literal dummy `visible-ref` from the prompt or invented a cell ref while the observation contained `controls: []`. The [offline train-only replay](evidence/full-study-v065-nonfinal-offline-replay-2026-09-27.md) verified the original response digests and checked nine preserved Desktop replies against fresh synthetic frames: v0.6.4 accepted one minimal action shape, while the proposed v0.6.5 accepted five; the four nonexistent refs **still failed**. That replay did not recreate the original current frame, call a provider, dispatch an action, or add a task score.

The proposed [v0.6.5 adapter](../src/cursibench/scale_action_output_v065.py) makes exactly two cell-neutral, pre-result changes:

1. Parse one whole-response JSON object as before. If it has **only** a top-level string `action` and no `type`, rename that field to `type`. A response with both fields, a non-string alias, duplicate keys, extra fields, invalid JSON, prose, multiple fences, an unknown action, or a stale/disabled/invented ref still fails. The resulting object is passed through the **unchanged** v0.6.2 minimal-action and full current-frame validators. No target is guessed, moved, or converted.
2. Keep the v0.6.4 model instruction byte-identical except for its version label and one phrase: replace the literal `{"ref":"visible-ref"}` placeholder with prose requiring a ref copied from a visible enabled control when the current list is nonempty. The screenshot, controls, action budget, and teacher/student role are otherwise unchanged. A speculative, longer coordinate-only prompt was tested on a training task and rejected after a 512-output-token malformed coordinate array; that failed prompt is not adopted.

Three bounded [real Qwen3.8/E2B training attempts](evidence/native-wdi-qwen-v065-nonfinal-live-2026-09-27.md) preserve both unsuccessful variants and the final minimal candidate. The final candidate passed the independently attested Desktop guest/profile boundary and applied two coordinate GUI clicks under a two-action cap, with no invalid action or provider error; the training file remained unchanged. This demonstrates an executable interface, **not** task completion or an improvement estimate. No new live sample happened to use the `action` alias, so the alias's direct evidence is the hash-bound offline train replay plus parser tests, not a claimed live alias dispatch.

**Adoption condition.** Before any researcher training or final scoring, all six cells must bind the exact v0.6.5 adapter/prompt bytes **and its v0.6.2/v0.6.4/full-validator dependencies** in the pre-campaign manifest, and use the same contract for base and selected checkpoints, rollout supervision, selection, and final evaluation. If this amendment is not adopted, v0.6.4 remains the study protocol and its invalid model replies must not be retrospectively relabeled. The historical v0.6.2/v0.6.3/v0.6.4 code and all original provider/GUI receipts remain intact. Official full-study admissions, model results, and researcher campaigns remain **zero** until the complete six-cell freeze passes.
