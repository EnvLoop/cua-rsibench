These local counts are not a provider invoice or final billed usage.

Two authenticated **read-only** `get_billing_usage` calls captured the same UTC window, **2026-09-28 14:00–18:00**. The first used the frozen run's Tinker SDK 0.30.0; a separate owner-only SDK 0.30.4 environment retrieved the newer billing fields without changing that runtime. Both private responses contain the same three organization usage events and one session entry. Two training events match the diagnostic's exact session `purpose`, plan-derived `run_id`, `split`, and base model. They report **53,234 + 9,979 = 63,213 training tokens**. Billing is hourly and session-attributed; it does not expose an immutable identifier for each of the 154 journaled operations. The third event is a checkpoint count without matching session metadata, so this audit does not assign it to the run.

The returned window has **no sampling-prefill or sampling-output events** for that tagged session. This does not establish that the 16 saved samples were free or that usage is complete. SDK 0.30.0 omitted estimated-cost fields from its typed response; SDK 0.30.4 returned an estimated cost for both matched training events. Its `cost_data_through` completeness watermark is null, and the queried window falls in the current incomplete UTC day.

It equals the nominal subtotal at the [published Qwen3.8-27B training rate](https://tinker-docs.thinkingmachines.ai/tinker/models/) of **$4.103 per million tokens**. This estimate covers only the currently returned, attributed training events; unreturned or unattributed usage, sampling, checkpoint and storage charges are outside it. The gross estimate precedes credits and commitments and is not invoice-reconciled. **Final billed tokens, total run cost, and invoice dollars remain unknown.** The earlier `$1.868022450` pre-run figure was a planning quote, not an invoice or a dispatch limit.
