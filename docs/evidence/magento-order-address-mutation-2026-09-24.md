## Observed result

The [public sanitized receipt](magento-order-address-mutation-2026-09-24.json) records a native 302 save, visible confirmation, and **1.0** from both unmodified official evaluators. The raw browser HAR and redacted HAR produced identical official results. The privately retained positive screenshot shows order #000000299 with the new billing address and unchanged shipping address. Raw HAR, login credentials, and authentication state were not retained; the privately retained redacted HAR contains only URL, method, status, and task-relevant form values.

An independent read-only SQL transaction found `sales_order_address.entity_id=598` changed from Oakland, California to `456 Oak Avenue\nApartment 5B`, New York, NY 10001. Magento also changed `sales_order_grid.entity_id=299`'s billing-address field. The other order's address and grid row did not change; full hashes of `sales_order`, `sales_order_status_history`, and `customer_address_entity` stayed fixed. The public sanitized receipt records row fingerprints and five table hashes without customer data.

The wrong-object negative repeated the same UI edit on order #300, billing-address row 600. Its real save returned 302 and changed row 600 plus order-grid row 300, while task 538's target row 598 and grid row 299 stayed unchanged. The unchanged official evaluator scored this trace **0.0**, with a network assertion failure rather than an infrastructure error. This shows the evaluator distinguishes the intended order from a plausible unrelated save.
