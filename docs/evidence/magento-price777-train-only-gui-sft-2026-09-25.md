# Train-only real-GUI vision SFT interface gate

This is a **development training-data gate**, not a model result or an official final task. The source is pinned WebArena-Verified Magento-admin task 777 at commit `6473f72db5dcefc97b5725b59e734504edc28a21`. Task 777, its template 742, and its five target product entities are quarantined from any final evaluation split. The prior task-777 base-model attempts remain pre-training diagnostics; this task cannot become a held-out post-training comparison.

A deterministic teacher operated a disposable, loopback-only Magento 2.4.6 clone through the validated GUI action dispatcher. It produced **36 current masked viewport screenshots and 36 one-action normalized JSON targets**, with the screenshot and visible-control list captured before each action. Login, evaluator, SQL, search-index, and reset state were host-only. The original executed assistant actions omitted optional memory while the teacher host carried working notes between turns. A separately hashed **action-only derivation removed those host notes from model-facing observations**; every action dictionary and masked screenshot byte remained unchanged. The student-facing turn contains the task instruction, current image, visible control descriptors, and previous action status. Raw screenshots, HAR, credentials, and both episodes remain in ignored private `work/` and are not release assets.

All five product saves returned the native success UI. The unchanged published evaluator scored **1.0** on both raw and sanitized network traces. Independent SQL readback confirmed the five requested product states and an unchanged wrong-color control. The search index showed the saved parent state; after the test, monitored SQL rows and all **181** search documents matched the pretask baseline. These checks admit this **single train-only demonstration**. Earlier failed recorder attempts were reset and excluded from SFT data.

The offline builder rendered all 36 action-only image-plus-action examples with `Qwen/Qwen3.8-27B`, `qwen3_5_disable_thinking`, `Qwen2VLImageProcessorPil`, and the pinned [Tinker cookbook](https://github.com/thinking-machines-lab/tinker-cookbook) commit `1e53aa3d1cdd6389b3290c2574641eccc0503242`. Every datum contained an image chunk and positive assistant loss weight; the largest supervised example was 2,610 tokens, including at most 1,395 image tokens. The render used Tinker SDK 0.30.1 offline and made **zero paid provider calls**. No optimizer update, checkpoint sampling, or student improvement has been measured on this GUI trajectory.

The next checkpoint compatibility step is a separately bounded, explicit `--paid-one-step` invocation of [`build_magento_gui_sft_v1.py`](../../tools/build_magento_gui_sft_v1.py) with the private admitted episode and a fresh ignored output directory. It is intentionally not dispatched by the offline command. The saved checkpoint path and sample stay private; any post-training evaluation must use a source/template/entity-disjoint task, not task 777.

The field-limited [receipt](magento-price777-train-only-gui-sft-2026-09-25.json) records the original and derived private hashes and split rule. A task-538 order-address attempt found that the native state selector did not respond to the existing permitted key actions; direct hidden-select mutation was rejected. A task-486 CMS title attempt reached a native save but failed the unchanged network evaluator. Neither rejected episode supplied training data.
