# Qwen3.8-27B base-model pilot on Magento task 777

This is a bounded **protocol-development pilot**, not a final benchmark cell or a training-improvement result. It uses the pinned [WebArena-Verified task 777](https://github.com/ServiceNow/webarena-verified/blob/6473f72db5dcefc97b5725b59e734504edc28a21/assets/dataset/webarena-verified.json) and its unchanged five product-save network assertions. A separate [scripted GUI oracle](magento-variant-price-qualified-2026-09-24.md) already established that all five green prices can be saved in a repaired local clone and independently verified. The two Qwen attempts below use the **base model**, with no Tinker training or checkpoint selection.

The model saw a current masked screenshot, visible headings, bounded memory, and a list of current control references. It could return one validated click, type, key, scroll, drag, wait, or finish action per Tinker sample. This is **DOM-assisted visual GUI use**, not pixel-only control: the references are derived from visible page elements, and the model has no selector, URL, shell, or application API action. A trusted host performed login and routed browser requests only to the disposable localhost clone. Product-save and validation POSTs were limited to the five task products; the Magento grid's own bookmark POST was also permitted. Model output never selected a backend endpoint. The host independently read SQL prices and search-index state, ran the unchanged published evaluator on raw and sanitized traces, then restored monitored SQL rows and reindexed all 181 product-search documents. Private screenshots, raw model text, HAR, and authentication state were not published.

The first observer called a DOM element “visible” even when its center lay around y=7,816, well outside a 1,000-pixel screenshot. Read-only replay mapped the selected `c100` ref to an unrelated product edit link. The original dispatch exception was summarized to `gui_dispatch_error` without retaining its class, so its exact class cannot be reconstructed. The revised [runner](../../tools/run_magento_price_model_pilot_v1.py) admits only controls whose click centers lie inside observed pixels, rechecks pixel and reference identity before dispatch, and stores any future dispatcher traceback privately. The model action grammar and task evaluator were not relaxed. Eight new offline tests pass, including a real Chromium offscreen-control test; the earlier fresh-frame suite also passes. A no-provider end-to-end local run exercised login, evaluation, and SQL/search reset before the retry.

All 40 retry samples completed at the provider interface; one changing screenshot was discarded under the stale-frame rule. The [masked terminal frame](magento-price777-qwen-base-budget-limit-2026-09-24.png) shows the keyword in the Products grid while the list still reports 2,040 records. Private action receipts show repeated clicks on the same keyword input after the fill, without an Enter key action. Neither attempt saved any of the five target prices. The wrong-color comparator stayed unchanged. The raw and sanitized official evaluations agreed on the diagnostic 0.0, and the monitored nine SQL business tables plus the complete 181-document product-search index returned to each clone's baseline. The second attempt's `sample_budget_exhausted` code describes a fixed action/sample ceiling; it is not a Tinker transport or Magento save failure. The private runner records the broad class `environment_failure` for that ceiling, while the public analysis separates it as **budget-censored without an infrastructure outage**. Both original private results remain immutable, and **neither is promoted to a scored model outcome or a success-rate estimate**.

At the [published Qwen3.8-27B rates](https://tinker-docs.thinkingmachines.ai/tinker/models/), the corrected first attempt used 17,833 rendered multimodal input and 100 returned output tokens, a nominal uncached subtotal of **$0.03372888**. Its immutable result accidentally omitted the 100 output tokens; the separate [correction receipt](magento-price777-qwen-attempt1-usage-correction-2026-09-24.json) reconciles five private usage records without altering that result. The retry used 101,811 rendered input and 826 returned output tokens, a nominal uncached subtotal of **$0.19398993**. The per-attempt worst-case reservation for 40 calls was $2.55252480, below the $10 cap. These figures are **published-rate token estimates**, not provider-billed tokens, credits, or invoice amounts; actual billing remains unknown. Exact run hashes and field-limited outcomes are in the [pilot receipt](magento-price777-qwen-base-pilot-2026-09-24.json).
