# Magento five-variant price task: rejected despite a published score of 1.0

This is a **failed admission test**, not a completed benchmark task or a model result. It concerns [WebArena Verified task 777](https://github.com/ServiceNow/webarena-verified/blob/6473f72db5dcefc97b5725b59e734504edc28a21/assets/dataset/webarena-verified.json): reduce the price of every green size variant of the Hollister Backyard Sweatshirt by $5. The pinned task has five separate network assertions for product IDs 111, 114, 117, 120, and 123. The exact dataset, task, and evaluator hashes are in the [field-limited receipt](magento-variant-price-rejection-2026-09-24.json).

A scripted GUI oracle signed into a fresh browser context against a disposable, mount-free Magento 2.4.6 clone bound only to localhost. It found each product by SKU in the admin product grid, opened its visible edit page, changed the displayed price from $52.00 to $47.00, and pressed **Save**. Each of the five native POST requests returned 302. Both the unchanged official evaluator on the raw private HAR and the same evaluator on a sanitized, price-field-only HAR awarded **1.0**. No model was called.

The [observed GUI screenshot](magento-variant-price-rejected-save-2026-09-24.png) instead shows the Magento error **“The stock item was unable to be saved. Please try again.”** An independent read-only SQL transaction found all five target `catalog_product_entity_decimal` prices still at $52.000000; the red XS comparator also remained $52.000000. Full hashes of nine monitored product, EAV, price-index, and stock-item tables were unchanged after the five attempts and matched the baseline at the final read. The clone exception chain reports a previous error, “Could not ping search engine: No alive nodes found in your cluster.” The private log was retained outside the public repository; its hash is in the receipt. This identifies the immediate local failure reported by Magento, without establishing that the pinned image always has a broken search service.

The official evaluator checked network events, including a 302, but did not establish that the requested prices persisted. The independent verifier therefore rejected this case: **0 admitted tasks** from this attempt. A wrong-color negative was not attempted after the positive could not persist. The qualification tool fails closed on SQL readback and checks transactional restoration of the selected rows plus complete monitored-table hashes. An earlier private diagnostic run exposed additional EAV and stock-item writes and prompted expansion of that rollback scope; the public receipt uses the clean rerun that ended with the baseline intact.

The [qualification tool](../../tools/qualify_magento_variant_price_v1.py) and its [focused tests](../../tests/test_magento_variant_price_v1.py) are provided for audit and repair. This one-clone finding is not evidence about model performance, general Magento reliability, 100-task readiness, or the full-scale study. It is a concrete reason to require visible save feedback and persisted-state readback before admitting a Magento mutation as a scored computer-use task.
