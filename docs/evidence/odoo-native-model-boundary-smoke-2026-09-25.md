# Odoo native screenshot/action and Qwen3.8 sampling boundary

**Status, 2026-09-25:** A native Odoo browser adapter now constructs the same `scale-computer-use-v0.6` screenshot-plus-visible-control observation used by the shared model contract. It accepts exactly one current-frame validated GUI action at a time. The model cannot supply CSS selectors, arbitrary URLs, shell commands, Odoo XML-RPC, SQL or filesystem operations. The adapter binds a fixed 1440 x 1000 viewport, a 90-action and 720-second task envelope, the Qwen/Qwen3.8-27B model identifier, `qwen3_5_disable_thinking` renderer and SHA-256 hashes of the adapter, shared action contract and vision proxy.

The [public-safe native-adapter receipt](odoo-native-model-boundary-smoke-2026-09-25.json) covers two controls. In static Chromium HTML, a visible-ref click and fill succeeded, while replay of a used frame and a changed screenshot were rejected. In **original Odoo Community 18.0**, a train-only actor received a real current screenshot and visible controls, then searched for and opened a train RFQ using three validated GUI actions. The independent Odoo business reward remained at its unsolved baseline; the worker's complete database and filestore restored exactly. Neither control called a model or used a hidden final task.

One bounded [Tinker Qwen3.8 train-frame sample](odoo-qwen38-train-frame-smoke-2026-09-25.json) then passed the *same train-only observation* to the pinned multimodal renderer and Tinker SDK. The provider completed one request. The renderer reported 4,923 input tokens, including 1,395 image tokens, and the response contained 216 output tokens in 14.85 seconds. These are rendered/returned token counts, **not a bill**: provider-billed tokens and USD cost were unavailable. The base model's output failed the strict JSON action parser (`invalid_action_json`), so **no model action was dispatched**. This is an interface and failure-classification result, not a task success/failure score or a checkpoint improvement. The train worker restored exactly after the call. The model saw no hidden final task, evaluator gold or host-only SQL state.

The [runtime binding receipt](odoo-qwen38-runtime-2026-09-25.json) pins Tinker SDK 0.30.0, Torch 2.13.0 and the exact Tinker cookbook Git commit `1e53aa3d1cdd6389b3290c2574641eccc0503242`, plus hashes of the shared action contract, vision proxy, Odoo adapter and original sampling receipt. It retains billed-token and USD fields as unavailable instead of treating rendered tokens as an invoice.

The actor-visible 11-step train-only positive trajectory is stored separately in ignored private evaluator storage with screenshot files, visible-control labels, normalized actions and rendered model-facing text. Its host QA independently scored reward 1 and proved its source group is absent from official hidden task identities. SQL/gold QA was not mixed into the model-facing trace. Before paid campaigns, the shared per-campaign call and dollar caps, application start state and checkpoint selection still need an atomic pre-campaign freeze; this one-frame smoke does not discharge those gates.
