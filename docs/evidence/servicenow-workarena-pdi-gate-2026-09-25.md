## WorkArena source and entitlement

The pinned [WorkArena code](https://github.com/ServiceNow/WorkArena/tree/87a9e61c2bf9c1d8271effe0f7e290860f0b252d) is Apache-2.0; instance access has [separate gated conditions](https://huggingface.co/datasets/ServiceNow/WorkArena-Instances). The upstream [README](https://github.com/ServiceNow/WorkArena/blob/main/README.md) describes 19,912 L1 *instances* from 33 atomic *tasks*, and 682 WorkArena++ compositional *tasks*. These denominators are different units and are not runnable identities here. The pinned source archive used for inspection has SHA-256 `e1405077071ee3c104f1e9399bb05ff6148ca280d113c31eb5695d809e79ebde`.

The gated [usage scope](https://huggingface.co/datasets/ServiceNow/WorkArena-Instances#usage-scope) permits benchmarking, evaluation, and research; it forbids training, production workloads, and sensitive/proprietary/personally identifiable data. The card also states fair-use and availability limits and no persistence guarantee. The proposed Tinker training loop therefore cannot collect training trajectories from these gated instances. Training must use a separately permitted source; the WorkArena instances can be considered only for evaluation/research within their terms after approval.

At the pinned code revision, [`SNowInstance`](https://github.com/ServiceNow/WorkArena/blob/87a9e61c2bf9c1d8271effe0f7e290860f0b252d/src/browsergym/workarena/instance.py) can load the gated pool or a separately configured custom pool. The task code has `setup`, `validate`, and `teardown` methods. In particular, [form validation](https://github.com/ServiceNow/WorkArena/blob/87a9e61c2bf9c1d8271effe0f7e290860f0b252d/src/browsergym/workarena/tasks/form.py) reads the created record through the Table API, but its source comment explicitly limits the check to expected fields; its teardown deletes tracked created records. [Compositional teardown](https://github.com/ServiceNow/WorkArena/blob/87a9e61c2bf9c1d8271effe0f7e290860f0b252d/src/browsergym/workarena/tasks/compositional/base.py) invokes each subtask's teardown. These source capabilities do not prove complete reset of arbitrary agent side effects, hidden verifier independence, or 100 successful task setups.

**Executable admission gate after approval:** fetch the approved pool only in a trusted controller; run one pinned L2 task through the actual ServiceNow GUI; read the saved records independently; calibrate an untouched baseline, an oracle-positive, and a wrong-object negative; then execute teardown and compare the relevant pre/post tables, attachments, ACLs, and background effects. Scale only after 100 identities pass that same gate. Keep instance secrets, evaluator gold, and private links out of the public repository.

## Separate Personal Developer Instance route

An original ServiceNow [Personal Developer Instance](https://www.servicenow.com/docs/r/application-development/personal_developer_instance_guide.html) is a possible **development prototype**, not WorkArena provenance. The current official guide says each Developer Program member may have one free PDI for learning, exploration, and experimentation, and that PDIs are not for business or production use. Actual release capacity can require a [waitlist](https://developer.servicenow.com/print_page.do?category=developer-program&identifier=obtaining-a-pdi&module=guide&release=yokohama). No PDI account or tenant was provisioned for this study; the right to run a high-volume automated publication workload on a PDI has not been established.

The official [reset-and-wipe procedure](https://www.servicenow.com/docs/r/application-development/building-applications/resetting_your_pdi_to_its_initial_state.html) deletes customizations and can take a couple of hours. It cannot serve as a per-attempt 100-task reset. A PDI prototype would need evaluator-owned seeded records, task-level restore/readback, wrong-object checks, and a GUI save path. It would be reported as a newly authored ServiceNow study, with its own source and workload permissions. If PDI terms or throughput do not cover the full experiment, the ServiceNow cell needs an authorized dedicated research or non-production instance.
