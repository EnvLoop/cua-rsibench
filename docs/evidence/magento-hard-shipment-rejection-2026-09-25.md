# Hard Magento shipment task: GUI persistence without an admitted control

Published WebArena-Verified Magento-admin task **499** is in the source hard subset. Two separate no-mount Magento 2.4.6 clones were created from the pinned image on loopback ports. Both used the unchanged source task and evaluator. This was deterministic GUI qualification with no model or paid-provider calls. The task's tracking number and evaluator form values are omitted from this public record.

The first clone reached the target order through the real admin UI and submitted a shipment with tracking. Independent read-only SQL found **one target shipment and one matching track**, while the adjacent comparison order had neither. The sanitized HAR scored 1.0, but the raw and sanitized evaluations disagreed. The raw score was not retained after the temporary HAR was deleted, so this attempt was **rejected**, despite the persisted state. The discrepancy arose during a HAR capture mode that omitted request-body text; a rewritten task-only HAR cannot be substituted for the native raw trace as proof.

A new clone from the same image used full-content HAR capture. Its visible shipment submission timed out waiting for navigation, and independent SQL found **zero shipment rows for both target and comparator**. The local Elasticsearch endpoint became unresponsive and then refused connections after an isolated restart. No official evaluator result was accepted for this retry. Both clones and their anonymous volumes were removed; the shared Magento smoke and separate Odoo containers remained running. The [field-limited receipt](magento-hard-shipment-rejection-2026-09-25.json) keeps the two failure modes separate.

This is an environment and evidence-capture failure, **not a model score** and not proof that the task is unsolvable. Task 499 remains provisional. Before retrying it, the admission runner needs a stable prewarmed search service, a raw trace whose body is available to the unchanged evaluator, a native GUI positive and near-miss negative, independent shipment/track readback, unrelated-state checks, and a fresh baseline reset for each case. The Magento cell still has zero official final identities.
