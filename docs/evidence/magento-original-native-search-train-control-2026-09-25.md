# Original Magento catalog task: native-search train-only GUI control

**Development scope, 2026-09-25.** This is one evaluator-scripted training-source task, not a model attempt, a hidden final ID, or a 100-task Magento result. The [field-limited receipt](magento-original-native-search-train-control-2026-09-25.json) binds the private source package, screenshots, saved-state snapshots, two neutral saves, GUI positive and wrong-variant negative, and exact cold reset without publishing the task text, supplier quote, product identity, gold price, credentials, or raw browser state.

The pinned Magento Open Source 2.4.6 image is Linux `amd64`. On this ARM host, its embedded x86 Elasticsearch 7 startup was not reliably available on fresh clones. [Elastic publishes a native ARM64 Elasticsearch OSS 7.10.2 image](https://www.docker.elastic.co/r/elasticsearch/elasticsearch-oss), and [Adobe documents a separate search server and catalog reindex](https://experienceleague.adobe.com/en/docs/commerce-operations/configuration-guide/search/configure-search-engine). We attached one fresh, mount-free ARM64 search container to each fresh, mount-free Magento clone on a dedicated network; the embedded service was stopped. The native catalog reindex produced **181/181 search documents with the exact canonical source-index hash** from the original image. Both application and search image digests are in the receipt. A first build attempt in the second pair failed to reindex; the failure was retained, a bounded retry on the same unseeded containers succeeded, and a read-only pre-task audit verified the runtime before source seeding. The transient failure is infrastructure evidence, not a model zero.

The first direct native price save on an unnormalized sample-catalog product persisted the intended price but also materialized target product defaults and altered stock policy. The strict independent verifier scored **0.0** because a target's `manage_stock` and related stock fields changed. We did not waive that substantive side effect. Trusted setup instead performed a **neutral native GUI save at the unchanged starting price** before freezing the task baseline. The neutral save left the quote, target price, unrelated catalog records, seven monitored business tables, and unrelated search documents unchanged. A narrowly scoped trusted step then set only the target product's automatic `updated_at` to a declared timestamp; an independent readback rejected any other field change.

On the normalized baseline, the scripted actor opened the supplier quote through Magento's native Content → Pages GUI, followed its policy, searched the named child SKU in Catalog, and saved the derived price. Independent SQL and search-index readback scored the **positive 1.0**. A fresh pair of app and search containers, with different container identities but the same pinned images and ports, repeated trusted source seeding, neutral GUI save, and timestamp finalization. The two complete monitored baselines matched **byte-for-byte in their canonical JSON snapshots**; the [fresh-reset auditor](../../tools/audit_magento_original_fresh_reset_v1.py) checked both app and search identities, source bindings, saved state, and every monitored full-table/index hash. From that second frozen baseline, a visible GUI edit of a plausible wrong variant scored **0.0** while the target remained unchanged. All actor actions were scripted development controls; no Qwen sample or researcher agent was involved.

This establishes one train-only application/reset/verifier path, including a real false-positive prevention case. It does **not** qualify the proposed 100 original final candidates, their five-variant policies, an account-wide cost envelope, a fixed Qwen screenshot/action adapter, or difficulty discrimination. Official Magento final tasks admitted: **0/100**. The local fourth-clone embedded-search failure and E2B custom-template provisioning failures remain separately documented in the [candidate inventory](magento-original-catalog-100-candidates-2026-09-25.md); their attempts are not assigned task scores. Actual E2B build charges are unknown.
