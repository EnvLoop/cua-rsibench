# A scored Qwen3.8-27B base-model attempt on Magento task 777

This is a **public-task development diagnostic**, not an official hidden-final benchmark result or evidence of training improvement. The model used the untrained `Qwen/Qwen3.8-27B` base sampler on [WebArena-Verified task 777](https://github.com/ServiceNow/webarena-verified/blob/6473f72db5dcefc97b5725b59e734504edc28a21/assets/dataset/webarena-verified.json). The task requires saving **all five** green variant prices at $47; a wrong-color comparator must remain at $52. A separate [scripted GUI qualification](magento-variant-price-qualified-2026-09-24.md) had already demonstrated that the repaired disposable Magento clone can satisfy the task. This model attempt did not.

The clone used the pinned Magento image on loopback-only ports with no mounts. On this ARM host, its embedded x86 Elasticsearch required a **clone-only JVM startup workaround** (Serial GC and C1 compilation) before reaching one healthy search node; the application task, seeded database, and published evaluator were not changed. A fresh no-model GUI positive/wrong-color-negative control passed and restored the monitored state before model dispatch.

The [field-limited receipt](magento-price777-qwen-scored-v3-2026-09-25.json) pins the v3 protocol SHA-256, source dataset and task hashes, immutable result hashes, independent database state, official evaluator diagnostics, reset checks, and token-use estimates. The local protocol artifact records a freeze at **2026-09-24 23:13:26 UTC**, before provider dispatch at **23:14:56 UTC**; this chronology has no external trusted timestamp. It specified a score of 1 only when the unchanged published evaluator returned 1.0 **and** an independent SQL check found all five target prices at $47 with the wrong-color comparator unchanged. A model termination or the no-visible-progress rule with unmet state scored 0; provider, GUI, verifier, capture, clock, or reset failures were unscored.

The model received a current masked screenshot and viewport-bound visible control references, then chose one bounded action per sample. This is **DOM-assisted visual GUI use**, not pixel-only control. Before each sample, the host required two identical masked frames and control identities 350 ms apart, with visible loading overlays absent; it discarded six unstable *local capture attempts* before sampling. After each provider response, it rechecked the frame and control identity. In this run **10 provider samples produced 10 applied model actions: seven clicks, two typing actions, and one `finish`, with zero post-sample stale responses**. The trusted host handled authentication, kept browser egress on the disposable local clone, and did not give the model a backend API, shell, or direct database action.

The final [masked native Magento confirmation frame](magento-price777-qwen-v3-one-of-five-2026-09-25.png) shows “You saved the product.” for the S-Green variant. Independent SQL readback confirmed that target product **114 changed from $52 to $47**. The other four target products stayed at $52, and the wrong-color comparator stayed at $52. The product-search index reflected the saved change. The model then chose `finish` without saving the other four prices. The runner recorded **0.0 on both raw and sanitized official evaluator passes**, with no evaluator error. An independent replay of the retained sanitized trace reproduced 0.0; the raw trace was deleted after its runner-side evaluation and cannot be replayed. The v3 runner recorded `completed`, `model_failure`, and `requested_prices_not_all_persisted`. This is **one scored failure with partial task progress**, not a five-product success or a success-rate estimate.

For v3, the independently read target price returned from $47 to $52 after reset. This monitored scope does not assert byte-for-byte restoration of every Magento service or account artifact. Private full frames, raw model text, network traces, credentials, and authentication state remain outside the public repository. The public screenshot is masked and only demonstrates the single saved product. Task 777 and its solution are public, so this attempt contributes **zero official final-task identities** to the planned full-scale study.
