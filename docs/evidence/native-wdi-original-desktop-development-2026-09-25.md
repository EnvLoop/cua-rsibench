# Original WDI/LibreOffice desktop development controls

Checked 2026-09-25. This is **train-only development calibration**, not a full benchmark result. The data is a [World Development Indicators](https://datacatalog.worldbank.org/search/dataset/0037712/world-development-indicators) API response frozen under SHA-256 `cad6aafbd856ebb78f3f50106ab1b5b38ac369a2da251e2442268e296fde6d9f`, with 1,050 nonmissing country-year-indicator observations. The catalog identifies WDI as public and [CC BY 4.0](https://datacatalog.worldbank.org/public-licenses). The authored Office documents use real WDI values in simulated analyst workflows; they are not historical company files. See the [pre-result desktop amendment](../FULL_STUDY_DESKTOP_SOURCE_AMENDMENT_2026-09-25.md) for why this original track is separate from OSWorld.

The [field-limited receipt](native-wdi-original-desktop-development-2026-09-25.json) binds a private candidate inventory SHA-256 `85666453d5ec30cb15667997d314d5c55df0fd4ff2a3af7ea73e77b98f215a04` and private split-map digest, without releasing final task identities or oracles. The generator creates **20 training, 20 selection, and 100 final candidates**. The final candidate mix is 50 Calc, 25 Impress, 25 Writer, across 25 country source families. This is an offline inventory count, not 100 runnable/admitted tasks.

Nine distinct E2B Desktop Linux sandboxes formed the three selected actor-control trios: one GUI positive, one GUI near-miss, and one cold-reset instance for each application. A **tenth, separate sandbox** performed a neutral LibreOffice save of the original Impress PPTX before those Impress actor attempts. All reported LibreOffice **7.3.7.2** and the same `/usr/bin/libreoffice` SHA-256 `eb926ee03b6ba1b18e89b4a94cbb7a060ceac31f171b4bf9db5677e848451f86`. Trusted setup uploaded the exact same input within each trio; the actor used screenshots plus native mouse/keyboard operations and Ctrl+S. Trusted evaluation downloaded the actor-saved Office bytes *before* any evaluator postprocessing. Every sandbox was killed and independently observed stopped. Full screenshot/action receipts stay in private ignored storage; public train-only inputs and saved artifacts are in [`native_desktop_factory/dev-fixtures`](../../native_desktop_factory/dev-fixtures/).

The first Calc positive attempt exposed a verifier bug: opening/saving the workbook made LibreOffice write cached results for two existing, unchanged formulas that `openpyxl` had left uncached. The old verifier counted that as collateral alteration and rejected the attempt. The verifier now compares unchanged formulas while allowing a previously absent cache to be populated; source observations remain immutable and the edited target still requires both the expected formula and a correct recalculated cache. A **second live Calc positive** passed under the corrected verifier. The failed calibration receipt is retained privately and excluded from the nine selected controls.

The original Impress positive initially passed a text-only verifier but failed a new visual-layout guard: stock LibreOffice changed the slide canvas slightly and shortened multiple untouched text-box extents, in one case by over two inches. We therefore **exclude** that first Impress trio from the selected controls. A neutral trusted save in a separate sandbox produced a LibreOffice-normalized input (SHA-256 `44b56a796b84af002c9c598d5d2508da21e2708145774e6b0c30c607a9049ceb`). Three subsequent fresh sandboxes produced a correct GUI edit, a wrong-signal GUI edit, and byte-equal cold reset. The stronger independent verifier checks slide canvas, all slide/text-shape counts, target text, all non-target text, and shape geometry. The positive passed and near-miss failed only at the target. This normalization is a **development workaround**; the 25 final Impress candidates have not been normalized or admitted.

The three positive/near-miss output pairs can be rechecked without cloud access using the [independent verifier](../../native_desktop_factory/verify.py) and [tests](../../tests/test_native_desktop_factory.py). These tests do not prove the full E2B action trace, but the field-limited receipt binds the private screenshots, actor action counts, sandbox identity hashes, saved bytes, and teardown observations. No model generated these edits.

**Admission at this revision: 0/100 final identities; official model attempts: 0.** Every final identity still needs its own saved-artifact positive, near-miss, and cold-reset control, along with a pinned full image/profile and difficulty validation. The four workflow templates are shared across train/selection/final despite distinct country source families; the current matrix contract forbids that overlap. The proposal is therefore **not yet eligible** for a pre-campaign freeze, even if the missing 100 GUI trios were subsequently run. Renaming template labels by split would not repair the scientific leakage boundary.
