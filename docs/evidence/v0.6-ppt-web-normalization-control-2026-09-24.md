The source is PPT-Eval revision `1b8b55a29e48fdc65d423689b6f2370ad91beeea` and was kept outside the public repository. A guard frozen against the raw source correctly fails, even if Office-derived metadata is allowed (77 unexpected parts). It is unsafe to treat an arbitrary raw PPTX as the post-upload baseline.

The two Office-saved artifacts differ in only five parts: `ppt/slides/slide1.xml`, `docProps/core.xml`, `docProps/thumbnail.jpeg`, `ppt/changesInfos/changesInfo1.xml`, and `ppt/revisionInfo.xml`. After removing only the target title run's `sz` attribute, the slide 1 XML is canonical-equal. The four remaining parts contain the observed modified timestamp/revision, command/revision IDs, and a derived JPEG thumbnail. Their narrow allowance is opt-in through `office_web_normalized=True` in `tools/pptx_title_size_guard.py`; all other slides, layouts, diagrams, notes, relationships, and media stay under exact or canonical comparison. Content changes to the core document title, change-record name, other slide, or media still fail. The derived thumbnails were inspected visually and show the expected title-size change on the same cover layout.

With the Office-saved control as the frozen baseline, the strict default artifact guard scores 0 because of those four derived parts; the opt-in guard scores 1.0 with `target_correct=true`, `preservation_pass=true`, and no unexpected parts. This is an **artifact-only conditional result**. The manually prepared control is not yet an automatically frozen evaluator baseline, and the upstream PPT-Eval renderer/official score was not established for this run. The case is therefore not admitted as a qualified final task. A production task must freeze the normalized baseline independently before the actor runs, preserve the exact source and control digests, and report renderer failure as unscored.
