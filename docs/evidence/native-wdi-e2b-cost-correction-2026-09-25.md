# E2B Desktop normalization cost-bound correction

Checked 2026-09-25. The two original native Impress normalization batches completed and verified sandbox teardown, but their planning receipts used **$0.35 per sandbox-hour** as an assumed upper rate. A later live Desktop probe observed **8 vCPU and approximately 8 GiB RAM**. The [E2B published pricing table](https://e2b.dev/pricing) lists $0.000112/second for 8 vCPU and $0.000036/second for 8 GiB, totaling **$0.5328/hour** of marginal compute at that resource class. The $0.35/hour field is therefore **invalid as an upper-bound reserve**; it must not be described as a compliant cost ceiling or as actual billed usage.

The original batch receipts remain preserved unchanged. Their 300- and 1,000-second server leases and verified termination bounded running time. The [field-limited correction](native-wdi-e2b-cost-correction-2026-09-25.json) binds the receipt hashes, attempted/adopted counts, observed wall times, and measured resource class without releasing sandbox IDs or provider credentials. At a conservative **$1/hour** planning bound, the full lease reserves would have been approximately **$0.0833** and **$0.2778**, respectively. These are reserves, not invoices. Actual E2B charges, credits, discounts, and subscription fees are **unknown** from the available SDK receipts and must be reconciled with provider billing before a cost claim appears in a paper.

Subsequent GUI sweeps reserve at $1/hour, cap each server lease, and reject a measured desktop shape above the priced 8-vCPU/8-GiB class. Later neutral-save batches also reject a caller-provided rate below the published $0.5328/hour marginal compute rate. The correction changes financial interpretation only; it does not retroactively alter task content, GUI outcomes, source rights, or official admission counts.
