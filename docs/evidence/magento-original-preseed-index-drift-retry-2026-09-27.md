# One bounded fresh-clone recovery of Magento pre-seed index drift

The [dated failure receipt](magento-original-preseed-index-drift-2026-09-27.md)
remains the record of a fresh Magento pair that failed the frozen search-index
gate before task seeding. Under the [pre-result one-case rule](../FULL_STUDY_MAGENTO_PRESEED_INDEX_DRIFT_RULE_2026-09-27.md), a private read-only audit rebound that pair to the failed preparation interval, unchanged source data, zero quote pages, pinned images, and zero mounts. The controller recorded cleanup intent and retired only those exact two disposable containers. The original diagnostic bytes and append-only failed journal were retained.

The single allowed retry then used two new app/search pairs with the unchanged
private candidate, pinned source, visible Magento admin controller, and
independent saved-state verifier. Both new pairs passed the frozen 181-document
source-index hash before task seeding. The full positive control scored **1**;
the wrong-variant control scored **0**; the cold-reset comparison passed; and
both pairs were cleaned. The [field-limited recovery receipt](magento-original-preseed-index-drift-retry-2026-09-27.json) binds the private audit, cleanup, retry journal, and final calibration hashes without exposing task content or container identities.

This is one **development GUI control**, counted once in the [32-candidate checkpoint](magento-original-gui-progress-32-2026-09-27.md). The original infrastructure failure is still counted separately. No model ran and no official final task was admitted.
