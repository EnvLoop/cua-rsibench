# Original WDI PowerPoint-web candidate inventory (2026-09-25)

The [machine-readable aggregate receipt](ppt-wdi-original-offline-inventory-2026-09-25.json) binds the private candidate plan and builder. This source track uses the repository's [pinned WDI snapshot](../../native_desktop_factory/sources/wdi-2019-2024.json) and the [source validation](../../native_desktop_factory/source.py). The observed data are authentic World Development Indicators values; the analyst deck and committee rule are authored simulations. No private country assignment, final task instruction, exact answer, account identity, or download URL is in this public evidence.

The inventory has 20 training, 20 selection, and 100 final **candidates** across 5, 5, and 25 disjoint country families. The country partition was verified against the existing original-desktop WDI partition so desktop training countries do not enter PPT final candidates. It is not a set of 100 independently sourced countries. Eight final causal workflows differ in indicator, time window, formula, or decision rule. Training tasks require one correction, selection tasks require three, and final tasks require four. Each final task has a seven-slide PPTX with a source table, native line chart with an embedded Excel data workbook, summary, calculation table, analyst finding, decision, and attribution; four dependent edits span four slides. All derived answers use the rounded WDI values visible in the deck, avoiding a hidden-precision mismatch. The frozen source hash, per-task oracle, and direct-OOXML positive/near-miss/collateral/chart controls live only in evaluator-private storage. The aggregate receipt records the number that passed the offline controls.

All 140 private decks passed package-integrity and layout-geometry checks, and all 140 passed the direct-file controls. One final candidate from each of the eight workflows was rendered as a seven-page PDF with the bundled LibreOffice runtime; pages 1, 4, 5, and 6 were visually inspected for clipping, missing text, broken tables, and layout drift. That render is a local compatibility check and does not establish that Microsoft PowerPoint for the web can edit or save these decks.

**Evidence limit:** these are candidate files and direct-file fixtures. No Microsoft PowerPoint-web source copy, GUI action sequence, saved download, Office-normalized oracle, per-ID fresh reset, hidden perturbation, or model score is established here. Therefore the official PowerPoint-web final set is still **0/100**.
